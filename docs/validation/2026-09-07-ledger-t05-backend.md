## 运行政策与限制

- 功能必须显式打开，当前生产未启用。时间配置严格 HH:MM；全局开关仅接受精确 true/false。默认窗口为周六 `[08:00,24:00)`，无历史周槽生成，周日不重采周六；同一已成功任务不因改时刻再执行。
- 每 tick 新建/处理各最多 20 个，旧过期/中断清理各最多 20 个；串行 12 秒总预算，失败清理另限 3 秒；轮后一分钟等待及临近计划时刻唤醒。重试 5/30 分钟、总计三次，中断同样消耗次数。高账户量/慢来源可能使任务错过当日，明确过期而不倒填。
- task 时间保存 UTC 纳秒 RFC3339，计划业务日按 Asia/Shanghai；实际报价日期和时间原样保存，不承诺周六成交或最后一个交易日收盘。沿用现有参考报价校验，没有新增交易日历、历史采集或固定旧报价过期天数。
- weekly_jobs 保留最近一次尝试状态/时间和总次数，不是逐次日志表；错误只存固定分类。全库不可写时可能暂留 running，数据库恢复后由租约/重启恢复；读取状态从不负责推进它。
- 模块文件独占锁和单 worker 是运行边界，不支持同一个数据库句柄手工构造多个调度器；fake provider 必须遵守 context，生产适配器有固定 HTTP 超时。未改当前全账本重放的容量限制。
- 自动观察只进入 holdings 历史及其已有分析。reported 和 holdings 不自动相加/切换，不把自动资产复制进 reported、不推断持仓、不补资金流。**同账户历史导入与未来自动总额的选源/资金流衔接仍未完成**，不能宣称已得到统一连续的历史收益序列。
- 未实现 T05 前端、事件日任务、T07+、历史行情/公司行动回填、增量导入/批次撤销、目标提醒；没有真实账本、公开代理或生产启用验收。
