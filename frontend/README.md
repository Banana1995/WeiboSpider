# 行情与投资记账前端

独立的 Vue 3 + TypeScript + Vite 前端，使用按需引入、异步加载的 ECharts。当前实现白酒列表、单品趋势及投资账本；不修改微博页面或 Python 服务。账本按用户授权在 <http://43.130.247.183:5052/ledger> 匿名共享全部读写，任何人均可查看、导入和修改全部数据，请勿上传私人财务信息。已接入腾讯报价/汇率、资产记录、有知有行账户 XLSX 导入、记录维护及收益分析；T07 同快照收益曲线、TWR/复合年化已实现，完整功能验收待执行。

## 本地启动

建议使用 Node.js 22 LTS（22.12+）或 24 LTS。本次验证环境为 Node.js 25.2.1。

先在本工作树的 `backend/` 目录启动 Go 服务：

```bash
go run ./cmd/server
```

新库需要显式同步一次；前端不会主动采集：

```bash
curl -X POST http://127.0.0.1:5051/api/platform/liquor/sync \
  -H 'Content-Type: application/json' -d '{}'
curl http://127.0.0.1:5051/api/platform/liquor/sync
```

等待状态为 `succeeded`。随后在 `frontend/` 目录启动前端：

```bash
npm ci
npm run dev
```

打开 <http://127.0.0.1:5173/liquor>，`/` 也显示同一页面。端口固定且冲突时拒绝启动，不占用微博的 5050。开发数据保存在被忽略的 `backend/data/`，不会加入版本控制。

默认开发代理仅将 `/api/platform/liquor/*` 原样转发给 `http://127.0.0.1:5051`。可通过启动 Vite 时的 `BACKEND_PROXY_URL` 改变目标。若后端启用认证，将同一 `BACKEND_API_TOKEN` 通过服务端环境传入 Vite；不要使用 `VITE_*` 变量承载密钥，也不要写入源码。记账代理需要单独显式开启，见下文。

此代理仅用于本机开发。生产构建不会携带 Vite 代理配置，正式代理由下述 Nginx 提供。Vite 开发服务器不能当生产服务。

## 本地记账

先在 `backend/` 启动记账后端，不需要采集白酒：

```bash
LEDGER_ENABLED=true BACKEND_ADDR=127.0.0.1:5051 LIQUOR_AUTO_SYNC=false go run ./cmd/server
```

在 `frontend/` 启动带本机记账代理的开发服务：

```bash
LEDGER_DEV_PROXY=true npm run dev
```

打开 <http://127.0.0.1:5173/ledger>，无需登录。端口已占用时不要停止不明进程，可为后端另设 `BACKEND_ADDR`，为前端设置相应 `BACKEND_PROXY_URL` 并传 `npm run dev -- --port <空闲端口>`。

### 正式账本界面

2026-09-10：`/ledger` 按已批准原型重做。**本轮在 `frontend/` 显式执行 `./node_modules/.bin/vue-tsc --noEmit` 和 `npm run build`，均通过，无需编译修复。按授权提交推送发布，部署结果以对应 GitHub Actions 为准；仅做只读 HTTP 可用性确认，功能验收由用户执行。不运行单元测试、完整测试套件、E2E、浏览器验收或独立审查，不写入生产财务数据，不重置数据库或数据卷。** 下文“验证”保留的是以前各阶段的结果，不代表此次界面已通过功能验收。

- 选择账户后自动读取最新资产、收益和有效记录，只调用已有 GET，不获取行情。最新资产来自 `effective-summary`，不受收益日期影响；收益来自同一 `analysis-basis` 快照，展示真实有效起止日。
- “记一笔”统一提供转入、转出、更新总资产三个等宽标签。转入、转出填写正金额，可选填资金变动后的总资产；总资产留空与明确填零不同。所有类型都可附备注，不再新增单独备注；已有备注记录仍可查看和修改。
- 个人视角使用后端 Modified Dietz 和 XIRR 年化，基金经理视角使用后端 TWR 与复合年化。切换视角不发请求，年化不由前端复算。成立以来、今年、去年、自定义是收益区间；缺期初、无区间、不可计算、沿用原值和短期年化均明确提示，不补零、不用示例数据兜底。
- 一张常驻记录表分别列出日期、类型、转入、转出、总资产、备注、操作。同一行的资金流和总资产同时保留，默认只读有效记录。筛选仅提供服务支持的日期与作废状态，不向接口发送不支持的类型参数，不把当前页数量当全账户总数。
- 分页使用服务器原始游标和上一页历史。资金标记按原账户、日期、记录 ID 定位真实记录，必要时逐页读取当天记录，最多 100 页；数据变化或达到上限明确提示，不从曲线快照拼造可编辑记录。
- 编辑、作废在原生抽屉对话框中完成。作废需要原因与确认；编辑需要修改原因和原版本，版本冲突保留草稿并要求重新读取。交易生成的账户记录只能前往持仓交易整笔修改；自动估值只能更正为总资产，来源由后端保留。
- “管理账户”包含账户资料、当前持仓、自动更新记录。资料只读，服务没有改名、改币种接口，不提供假保存按钮。新建账户使用一个表单，可创建普通总资产账户或带现金及多项期初的持仓交易账户。
- 当前持仓按 `current_holdings_input` 能力展示：独立快照可编辑现金与证券数量，明确空持仓可保存；交易重放来源不可覆盖。证券登记和八类交易录入、更正、作废在管理页保留，所需全局日内序号按实际先后填写。证券市场、代码、币种使用真实登记接口，不提供模拟价格。
- 管理页只有点击“预览当前估值”才获取参考行情；预览完整后点击“更新并保存总资产”才 POST 保存，服务会重新取价。保存持仓本身不产生资产记录或采价。页面不把旧幂等回执当成当前资产，成功后独立重新读取数据。
- Excel 导入从管理页或空账户入口进入，用户选择真实 `.xlsx` 后先上传预览、核对可读行内容和警告，再确认写入。仍仅支持空账户初始化，最多 8 MiB；不展示整份原始数据、JSON 或诊断列表。
- 自动更新页只在打开栏目时读取实际计划及任务记录，按当前账户分页展示；没有启用、立即执行或重试任务的按钮，也不触发行情请求。
- 所有金融金额、版本和标识保持字符串。写入或导入结果不确定时固定原始内容、账户、ID 和幂等键，锁定关闭、账户切换和导航，只能按原请求确认；刷新和离开有警告，强制关闭后内存请求不能自动恢复。未保存草稿关闭时确认并恢复焦点，不在浏览器持久化财务事实。
- 原始导入、冻结估值与统一审计接口仍保留，日常主界面不再显示审计、原始 JSON、计算依据或重复的收益表。`/ledger-prototype` 保持独立的内存演示，不导入正式写入组件、不请求账本 API。

以下分阶段说明保留接口背景；旧页面的面板位置与操作名称，以本节的正式界面流程为准。

- `LEDGER_DEV_PROXY` 默认关闭，开启时只接受回环 HTTP 后端地址；实际 socket peer、Host 及 Origin/Fetch Metadata 均检查，即使误传 `--host 0.0.0.0` 也不接受远端访问记账代理。不要通过隧道或其他代理绕过该边界。
- 账本代理保留原始 Host/Origin，后端仍进行同源写检查；清除 Authorization，不依赖服务令牌。此功能不会改变白酒只读代理。
- `npm run preview` 始终拒绝记账代理，即使设置 `LEDGER_DEV_PROXY=true`，避免继承 Vite 开发代理后被误当成公开服务；实际 preview HTTP 验证为 JSON 404。
- 页面入口为 `/ledger`；`/liquor` 与 `/` 保留白酒页面。采用普通同源导航链接，不引入新的路由、状态管理或 UI 依赖。
- 可创建账户及多项期初持仓、登记证券、查询现金与两种持仓成本，录入八类操作，按日期/账户/状态分页查看流水，整笔更正、作废及查看修订。
- 金融数字全程用十进制字符串。费用留空为未录入，期初成本留空为未知；金额、股数、价格和汇率精度由客户端初筛、后端最终校验。
- 全局日内序号须按实际先后明确填写，不按账户分别编号，作废记录仍占用序号。外币操作选好证券、账户及业务日期后自动获取腾讯汇率：北京时间今天用最新报价，历史日期用不晚于该日的日线收盘价。显示实际汇率日期、来源及最新报价时间，不是券商结算汇率。
- 已存交易更正默认保留原汇率；改变币种/业务日期或点击重新获取才替换。获取中或快照无效时不能提交。切换条件会取消旧查询，迟到响应不能覆盖新上下文。
- 获取失败明确提示，可重试或点击手工录入。手工模式清除原自动值和来源，填写正汇率、实际日期与来源，获取时间默认本次手工记录时间。写入只保存四字段固定快照，后续查询不会刷新旧账。
- 当前周期分红需先在账户详情读取对应持仓；迟到分红可明确填写旧周期 ID。尚无独立周期列表，不自动猜测归属。
- 写入结果不确定时锁定原始请求和幂等键，只允许按原请求重试；账户初始化先查询固定 ID 确认。成功写入后的读取失败不会被当成写入失败。待确认请求只存在页面内存，离开有警告，强制关闭后不能自动恢复；不在浏览器持久化私人账本。
- 两类账户都只在管理页显式预览/保存时查询报价，无后台轮询，持仓 PUT 成功不自动采价。总资产使用同一来源快照的现金加逐项折算市值，不使用成本，不混用另一次查询的现金或数量。
- 完整估值显示参考总资产；缺少任何非零持仓的报价或汇率则显示“不能完整估值”，只单列已知市值小计，不把现金或部分合计当总资产。清仓持仓为零且无需报价；现金账户直接以现金为总资产。
- 管理页预览显示原币报价与实际日期，非当日数据明确标注；刷新或失败时清空旧估值，不作为当前资产。完整保存来源仍由估值历史 API 提供。
- 自动报价支持 SH/SZ 白名单股票代码和 HK 五位代码，使用登记市场而非仅按代码猜交易所；沪市 B 股 `900` 为 USD，深市 B 股 `200` 为 HKD。证券登记币种必须一致。其他市场仍可记账，但不能据此自动估值。
- 打开账户、全局刷新和操作成功后的 GET 读取现有资产与收益，不自动请求估值。“更新并保存总资产”明确发送 POST `{}`，服务端重新计算；原键/原请求在不确定期间锁定，重试不重新采价或追加记录。明确失败显示错误；成功后刷新当前记录，不自动再次保存。
- 冻结估值历史 API 继续提供保存时账户名、证券身份和估值依据，不在正式账本主界面单独堆叠历史面板。查询这些 API 不会请求当前行情或增加记录。
- 初始化导入、人工和自动金额共用同一账户记录列表、资产图和收益快照，无轨道选择器。记录支持更正/作废及统一审计；操作生成的记录必须从原操作修改，自动资产更正标记人工确认并保留原报价。手工总额不改变持仓现金。周任务只读面板已实现；T07 个人/基金经理视角只切本地指标，不重新请求或持久化。趋势明确区分采样连线、参考和不可用，等价表每页 30 行。汇总未实现；取消的历史回填/增量导入/批次撤销没有恢复。

### 同账户当前持仓

选择导入或手工创建的总资产账户，进入“管理账户 / 当前持仓”后只读 GET。现金使用账户本位币，证券从现有登记表选择；点击“编辑持仓”可添加、删除、改数量并多次保存整份快照。现金最多 2 位、数量最多 6 位小数，全部保留字符串。无成本要求，无账户转换、切换日期或历史补交易。

- 保存当前持仓不修改导入资产/资金流、不生成交易或总资产；明确的零现金和空证券列表也是已配置来源。删除所有证券表示纯现金，不代表取消来源。
- 保存成功后可显式“预览当前估值（不保存）”或“更新并保存总资产”。后者重新获取报价并追加同账户记录；行情不支持或数据不完整时总资产未知，不保存小计。冻结估值显示来源持仓版本、保存时间和审计 ID。
- 版本冲突保留草稿并提示重新读取；网络结果不确定锁定原始字节、CAS 版本和幂等键，与导入、记录、估值及账户导航互斥。原请求重试确认后另读最新版本，不拿旧回执覆盖新状态。切换账户取消旧 GET，迟到响应不覆盖新账户。
- 已有交易账户只显示重放持仓，不开放手工快照覆盖；用户无需选择或切换记账模式。
- 本次只做合成单元测试与构建，不运行浏览器验收、E2E 或独立审查，不部署。后端是直接收敛的开发 fresh schema，不兼容旧库，不自动删除任何数据库。

### T05 周六调度（只读）

正式页面在“管理账户 / 自动更新记录”显示查询时的全局状态、北京时间每周六时刻及下一计划。默认关闭，配置仅由服务端管理；页面没有启用开关、立即执行或手动任务重试接口。启用不等于 worker 正在运行，状态不是心跳。下面保留的是 T05 原只读面板与 API 能力的历史说明，不代表新版主界面仍呈现所有技术字段。

- 面板账户选择独立于上方记账账户。首次加载和手动刷新读取 `/weekly-status` 与所选账户 `/weekly-jobs`；状态筛选、30 条游标分页、详情及关联冻结记录全部只读 GET，不调用父页面刷新或当前 `/valuation`，不抓行情、不保存记录。无账户时仍可查询全局状态，无后台轮询、SSE 或浏览器持久化。
- 显示 pending/running/succeeded/failed/skipped 的文字状态、最近开始/结束时间、已开始次数（最多 3 次）、最早允许重试时间及固定原因。全局关闭时历史 running 和重试时间仍可能保留，不声称此刻执行或未来必定重试。每次列表/详情是独立查询，状态可能已推进；旧响应取消且不能覆盖新账户/任务。
- 自动估值成功任务通过 `history_id` 打开同一账户的冻结估值，显示保存时账户/证券身份、现金、持仓市值、总资产及实际报价/汇率日期和来源。沿用成功任务直接在详情显示冻结的原始记录 ID、序号、版本、日期和金额，不调用估值历史。全部时间明确转换为北京时间，金额/ID 保持字符串。成功只证明当时保存，后续记账或更正可能使原始证据过期，此处不重新认证分析有效性。
- 旧版本曾通过刷新保存估值，旧记录保留；当前刷新仅预览，只有显式保存或周任务入账。history_id 关联才能证明周任务来源。有当前持仓来源时保存冻结估值；无自动来源时复制最近有效总资产，并显示原始记录日期、ID 和版本，不请求估值历史。
- 全部当前金额写入同一物理表，历史和后续记录直接用于同一曲线，不设来源桥接或切换日期。沿用记录明确标为“每周沿用”，不会把旧金额冒充现金、持仓或新行情；没有任何历史总资产时才显示未更新且不补零。
- 新增只读“操作审计”面板，按账户、对象类型和动作筛选，每页 30 条；详情按原始 JSON 文本显示，保留大数精度并转义。审计查询不会保存估值，也没有修改或删除审计接口。

接口见 [API 第 11 节](../backend/docs/ledger-api.md#11-周六总资产任务t05-后端)。既有 [T05 前端验收](../docs/validation/2026-09-07-ledger-t05-frontend.md) 保留改动前的历史范围；全账户沿用功能本轮只完成定向测试，等待统一验收。未使用真实数据，未提交、推送或部署。

### T04 收益分析

正式页面选择账户及收益日期后自动 GET 同快照分析，无需展开“分析依据”。收益概览与收益曲线使用同一当前记录快照，不抓行情或保存；独立的最新资产来自有效统计。切换账户/日期会清空旧结果。fresh schema 为全部来源分配同一稳定序号；更正保留原序号，不按修订时间重排。

未填开始日期时首个已知日终资产作为基准，排除该日资金流；明确开始日期时取此前最后资产。期末不延长到空白截止日，缺初值不补零，carried 只供参考且不加款，过期/未追踪端点阻止指标。短期 XIRR 有外推警告，无解/可能多解/精度不足分别说明，金额和百分数不经 Number 展示。详细契约和限制见 [API 第 10 节](../backend/docs/ledger-api.md#10-同快照收益t042026-09-07)，验证见 [T04 记录](../docs/validation/2026-09-07-ledger-t04.md)。

## 账户级 Excel 导入

在“管理账户 / 账户资料 / 导入 Excel 账本”中选择文件，点击“预览文件”，核对日期、类型、资金流、总资产、备注和警告，再选择新建总资产账户或现有账户并确认。上传预览不写库；新账户与整批记录在一个事务中保存。

- 导入账户级资金流、总资产、投资日志、明细及来源日期/创建时间，不关联、生成或推断证券交易、持仓、子账户或内部转账。名称含“汇总”也仍是一份账户数据。
- 同一行同时有资金流与总资产时保留两者；空总资产为未提供，不补零、不沿用旧值制造记录。相同日期/相同数值行也保留，来源行号是文件顺序，不声称是实际交易顺序。
- 新建总资产账户使用来源账户名和币种，不需要登记证券或填写期初现金；账户元信息 cash/opening_cash 对外为 null，导入本身不触发持仓重放或估值。此类账户不接受交易/转账，但可在同账户“当前持仓”面板配置独立估值来源，现金读取该快照字段而非元信息占位。
- 现有持仓账户也可接收同币种的账户级导入记录，其原现金、持仓、期初日期、操作及自动估值历史不变。两类记录分别展示，不相加、不互相覆盖。
- 保留账户目标、预期收益、投资期限、币种和资金分类。金额精确解析到分，兼容数值科学记数法；日期支持 Excel 1900/1904 日期系统，创建时间转换为 UTC 并保留原值。支持简单百分比样式及多行文本，复杂百分比样式会提示错误位置。
- 只支持 XLSX，单文件最多 8 MiB、解压合计 32 MiB、10,000 个数据行位置；公式、宏、外链和非法工作表结构拒绝。错误显示代码/行列，不回显私有单元格值。原文件只在请求内存处理，不保存到服务端临时文件或浏览器持久存储。
- 导入只允许初始化无业务记录的账户；原文件重试先查回执，不受后续人工/自动写入影响，也不覆盖修订。不同文件不增量合并或替换。编辑直接更新当前记录，原始导入及旧版本保存在统一审计。预览后改变文件须重新预览。
- 不确定提交保留原文件、目标 ID、摘要与幂等键，锁定页面写入和离开，只能原请求重试；提交已成功后读取失败不算导入失败。
- 原始导入内容仍可由 API 查询，正式页面不再渲染原始导入面板。主记录表与分析使用全部当前记录；表格按服务端日期/状态筛选和游标分页。金额按日和稳定序号取值，资金流只计算一次，资产更新不生成外部资金流。

导入开发依据用户提供的两份账户导出结构，但未把真实附件写入数据库或提交仓库。历史端到端测试使用生成的合成 XLSX；本次公开发布不运行 E2E、不导入用户附件。公网共享读写已获得授权，上传内容将向所有访客公开且可被修改。

公网匿名共享全部读写及部署已获得授权，不新增登录或用户权限控制；完整功能验收仍待安排，真实附件不自动导入。腾讯为非正式公开接口，字段或可用性可能变化；不能把参考报价视为券商保证成交价。

## 生产接入

入口为 <http://43.130.247.183:5052/liquor> 和 <http://43.130.247.183:5052/ledger>。`Dockerfile` 在 Node 构建阶段生成静态文件，运行阶段只保留 Nginx 和构建产物，不运行 Node/Vite 服务。

- Nginx 提供 SPA 回退；精确 `/api/platform/ledger` 及子路径匿名代理全部账本读写，清除 Authorization，保留含端口的 Host 以支持同源写校验。上传总请求限制 8 MiB + 64 KiB，连接/发送/读取超时分别为 5/15/30 秒。
- 白酒 `/api/platform/liquor/*` 仍只允许 GET/HEAD，公开 POST 同步返回 403；其他 `/api/platform/*` JSON 404，错误不通过页面回退掩盖。
- `BACKEND_API_TOKEN` 仅在 Nginx 运行时注入白酒上游请求，不进入 JS 构建产物或账本代理；浏览器不持有该令牌。
- 根 Compose 统一部署 `weibospider`、`platform`、`market-entry`，push `master` 触发共同发布，不是独立前端发布流水线。
- 原微博仍从 5050 访问；白酒/记账有同源导航，没有微博 Vue 页面或 `/api/weibo/*` 代理。
- 当前为 HTTP，账本按用户授权公开共享，无用户认证或权限隔离；不承诺私人数据保密。周六自动任务保持关闭。

具体部署及数据保护要求见 [部署运维](../docs/deploy-prep.md)。
