# 账户切换性能：会话缓存与传输压缩

## 范围

针对「21-25股票汇总」账户点击后等待收益和曲线的体验，实现 JSON gzip、会话内快照恢复和后台核对、指数共享缓存与限量空闲预取。未实现精简首页接口，也未改变收益计算、原接口结构或数据库。

## 基线排查

在生产版本 `63cba5f` 做只读观察：

- 点击后约 16 ms 进入加载状态，主数值/账户曲线约 1571 ms 显示；两个指数请求分别在约 1892/2289 ms 完成。
- `analysis-basis` 为 491,290 B 未压缩 JSON，浏览器该次 TTFB 约 411 ms，下载约 1139 ms；服务器内经 Nginx 读取三次为 61–65 ms。
- `points` 368 个、`curve` 306 个、`changes` 368 个。JSON 解析单次约 0.9 ms，下载后数值/Canvas 显示约 22 ms。
- 不把浏览器 TTFB 直接当作计算耗时；主要瓶颈为未压缩传输及每次切换重新读取。指数还需等待账户实际收益区间返回后再发起请求。

## 本地同条件对照

使用临时只读 HTTP 回放程序，将公网现有 GET 响应保持在进程内存，以相同字节提供给原版本前端和本次生产构建。原版本不压缩，本次配置使用 gzip 等级 5；Chrome 桌面、CPU 1x、Fast 4G 网络模拟。只操作账户选择，不写入生产、导入文件或触发采集，响应内容不保存进仓库。

以下为观察样本，不是线上 P95 或性能保证；回放不包括后端重新计算时间。

| 条件 | 收益数值/账户 Canvas | 两条默认指数就绪 |
|---|---:|---:|
| 原版本，首次进入 | 696 ms | 1020 ms |
| 优化后，首次进入（未预取） | 238 ms | 450 ms |
| 优化后，切回已查看账户 | 22 ms | 22 ms |
| 优化后，空闲预取完成再首次进入（两次） | 14–19 ms | 14–19 ms |

- `analysis-basis` 传输由 491,290 B 降至 52,230 B（约减少 89%）；同次指数响应由 79,162/81,182 B 降至 16,334/16,977 B。
- 缓存恢复时“已显示上次读取的结果，正在核对最新数据…”可见；后台响应完成后提示消失。切回时仍重新核对账户收益，但没有重复发送两条指数请求。
- 空闲预取在当前账户响应后至少 1.5 秒才开始；同轮最多两个相邻账户，请求顺序执行。
- 使用运行环境同版 Nginx 对临时配置执行 `nginx -t`，语法校验通过；未替换或重载生产配置。

## 正确性验证

- `npm test`：31 个文件、299 项测试通过；`npm run build`、`npm run format:check` 通过。
- 单元/组件测试验证：LRU/TTL/字节预算、同请求合并、订阅者取消隔离、失效后的旧响应拦截、写入后强制新读、404 删除结果清除、前台缓存恢复后更新、相同/覆盖/重叠指数区间复用与精确归零、预取顺序/数量与取消。
- 页面缓存与每个账本 workspace 同生命周期；持久化财务数据的浏览器存储未引入。未知前台账户先显示加载，缓存命中也不宣称已经核对最新记录。
- 本记录为本地性能对照；生产实际效果需要在发布后按同一操作复测。
