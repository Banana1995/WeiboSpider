# 单股持仓记账与自动现金分红

## 用户确认

- 持仓列表可进入单股详情，录入买入日期、股数、成交价，继续加仓、减仓、分红、修改或删除记录。
- 未填现金显示 0。填写实际剩余现金后，以这次余额及其时点为基准计算后续现金变动，历史买入不追扣；不新增 `cash_initialized` 状态。
- 自动现金分红按公告金额计算，允许手工更正到账金额或删除。第一版提供单股成本、盈亏与收益率。
- 个股统计独立于 `account_records` 的总资产、外部资金流和账户收益率。

## 数据与接口

新增迁移 `005_stock_journal.sql`，保留既有账户、快照、审计及幂等回执。

- `stock_entries`：版本化买卖/分红流水；删除为作废。现金分红保留公告条款、取得资格的股数、持有周期、派息日期和结算汇率。
- `stock_journals`：旧数量的待补录基准及最近一次明确现金余额。原有数量不伪造买入成本；详情提供“补录初始买入”和“移除旧持仓”。
- `stock_dividend_cache`：按市场/代码共享的公开分红事件和历史汇率缓存。
- `stock_dividend_status`：账户最近检查时间与同步状态。

`GET /api/platform/ledger/accounts/{id}/stock-book` 返回当前持仓、已清仓股票、原币成本收益、现金、持仓市值、总资金（现金加折算市值，行情不完整时为空）、每只股票占账户总资产的比例、交易与同步状态；最多 200 个证券、10,000 笔记录，界面分批展开记录。列表展示总资金、持仓市值、现金和每只股票的持仓比例，市值、持仓比例、持仓盈亏三列可点击表头切换升序或降序；手机端用排序按钮提供同样能力。

`POST` 到同一地址提交 `action`（`create` / `replace` / `void` / `cash` / `clear_opening`）、`expected_version` 和相应内容，要求 `Idempotency-Key`。新增股票与首笔交易在同一事务内创建。交易、现金与当前持仓快照、审计、回执原子提交；不创建账户的转入转出记录。开始使用交易记账后，旧快照替换接口拒绝绕过流水直接修改数量。

所有金额使用分币整数，股数/价格使用六位定点数，汇率八位。前端只计算填写时的金额预览，正式股数、成本、现金和收益由后端计算。

## 现金基准

现金表单填写的是“现在实际剩余金额”，不是入金。基准日前，以及同日已覆盖的交易，不重新扣减。自动分红在基准日及之前的到账视为已包含在余额中。之后按日期/同日顺序结算，现金不得为负，历史卖出也不得超过当时数量。

未设置现金基准的初始跨币种买入无需填写汇率（记录为未结算的 0 汇率）；参与后续现金结算的跨币种交易要求明确汇率。手工交易可读取腾讯参考汇率并调整。自动分红使用派息日历史汇率快照，无法取到时暂不计入现金、展示待补汇率；基准已覆盖的旧分红无需为现金重取汇率。

## 单股公式

腾讯官方网页版帮助及当前公开脚本提供参考：

- <https://gu.qq.com/sstock/quotpage/webhelp.htm>
- <https://gu.qq.com/i/aio_zixuangu.b23a6a6d.js> 中 `holdCost`、`dilutionCost`、`holdPl`、`holdPlRatio`、`allPL`、`ratePL` 和 `stockYKCalculate`。

普通买卖与现金分红场景：

```text
买入支出 = 数量 × 成交价（先舍入至分）+ 手续费
卖出净回款 = 数量 × 成交价（先舍入至分）− 手续费
持仓成本 = 本轮累计买入支出 / 本轮累计买入股数
摊薄成本 = (本轮买入支出 − 本轮卖出净回款 − 本轮应得分红) / 当前数量
持仓盈亏 = 市值 − 当前数量对应的本轮均价成本
持仓盈亏率 = 持仓盈亏 / 当前持仓成本金额
累计盈亏 = 市值 + 历史卖出净回款 + 历史应得分红 − 历史买入支出
累计盈亏率 = 累计盈亏 / 历史买入支出
```

清仓重买开始新轮，累计统计保留全部记录。摊薄成本可为负；无数量不计算单价成本，无价格不伪造盈亏。货币收益计算从精确金额分摊，不用已舍入的显示均价反乘数量。

## 自动分红

账本服务启动后后台每分钟检查已有交易账本，市场事件缓存六小时；用户写入后唤醒检查。数据请求在 SQLite 事务外执行，结算时重新读取账户当前版本。普通 GET/刷新只读取。

- 港股：东方财富 `RPT_HKF10_MAIN_DIVBASIC` 提供历史普通现金分红；异常时回退腾讯 `appstock/app/hkStockinfo/jiankuang` 的 `fhpx`。腾讯的 `real_pay_date` 才是派息日，样本中的 `PAY_DATE` 与除息日相同。
- 沪深 A 股：东方财富 `PC_HSF10/BonusFinancing/PageAjax` 的 `fhyx`，使用实施方案的 `EQUITY_RECORD_DATE`、`EX_DIVIDEND_DATE`、`PAY_CASH_DATE`；“10派”金额除以 10 转为每股金额。
- A 股以登记日收盘数量确定资格，港股以除净日前持股确定资格。除息日生成应得分红，派息日结算现金。清仓后的派息仍归属原持有周期。
- 按证券与事件去重，重复同步不增加第二笔现金。匹配日期已有手工分红时保留手工记录；编辑/作废自动记录后保持用户更正。
- 当来源暂时失败时，已缓存的确定分红仍可结算，并显示同步未完成。

### 数据覆盖边界

这是网站公开数据接口，不是券商真实到账流水。默认金额为公告口径，不自动代扣个人税费。沪深及腾讯港股备用接口只有近期窗口，已有旧缓存保留，未覆盖历史可手工补录；不宣称完整历史收益。无完整日期、无法明确识别的现金方案、B 股币种不明确的方案不自动记账。实物派发不变成现金；包含本股送转、拆合股的历史需要核对，相关后续自动分红会保守跳过。

## 验证

使用临时数据库、合成行情/分红进行 Store/HTTP/worker 单元测试，覆盖现金基准、成本公式、部分卖出、清仓重买、跨币种、权益日与派息日、重复检查、修改/作废、幂等、并发和回滚。前端覆盖列表到详情、三项买入输入、跨币种输入、现金指令不确定回执重试、全局锁和精确预览。

本地浏览器用拦截的合成数据检查桌面与 390px 手机布局。生产只做读取和健康检查；用户自行验收实际记账交互。
