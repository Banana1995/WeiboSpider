## 2. 数据库迁移

### 2026-09-08 当前持仓决定（取代旧兼容约束）

用户明确授权开发测试阶段直接收敛当前设计，无需旧数据迁移、回滚或兼容实现。本次直接修改 `001_init.sql`，不增加 `002`；迁移校验和保护仍保留，不自动删除/重置任何本地或生产库，不部署。旧库不能直接套用本次结构，未来实际启用须另行确认数据处置，本轮不执行。

`current_holdings` 是导入/总资产账户的独立手工当前输入，不是历史总资产，也不是交易重放缓存。按账户保存整份现金与数量 JSON、版本及对应审计 ID；不可变版本在 `audit_log`，与全局 `idempotency_receipts` 原子提交。现金可为零，数量必须为正且证券不重复，空列表为纯现金，缺行才是未配置。时间由服务器生成，不暴露转换日期、成本或账户模式开关。

当前输入能力与 `accounting_mode` 分开暴露：GET 账户返回 `current_holdings_input=manual_snapshot|transaction_replay`。交易账户继续用期初/交易重放，禁止快照覆盖；导入账户不需新建账户或补齐历史交易。持仓 PUT 不写 account_records、不请求报价；估值 POST 和周任务完整成功才写同账户资产，flow=NULL。

估值冻结 `source` 及手工来源的完整 `current_holdings`（版本、audit_id、saved_at、现金和数量），读取历史校验该不可变来源审计；保存前在事务内与当前快照精确比较，网络期间改动返回 basis_changed。分析水位纳入持仓审计，只使更新当天及之后、确实依赖旧手工输入的观察过期，不使之前日期或导入资产普遍过期。周任务入队按实际来源决定；pending/可重试 failed 的沿用任务可在领取事务内提升为持仓来源，触发器记录前后状态。成功及跳过任务仍终态，不重复执行。

估值阶段新增 `quotes.go`、`valuation.go`：腾讯股票批量报价、`GET /accounts/{id}/valuation` 和一次事务读取现金/持仓依据。网络请求在事务外，当前总资产按原币市值舍入、最新汇率折算、累加现金计算，不使用成本或修改历史交易。

GET/HEAD 仅预览当前估值，不写库。明确 POST 空对象并附幂等键才重新计算和保存：先在事务查历史回执，未命中后事务外获取报价，最后事务重查回执并保存 canonical、审计与原响应。已提交重试不会再次获取报价，后续更正不被恢复。schema-1 冻结证据只读，不能作为当前业务金额输入。

估值输入事务内还计算全局账本 SHA-256 指纹 ledger_revision，以标识读取依据；网络期间有新操作时仍保存原快照，而不拼接不同时间的现金/持仓。交易更正不覆盖旧历史，这些采样不能直接当成更正后账本的有效收益序列或历史收盘价。列表及详情 API、查询范围和后续格式演进规则见接口文档。

前端新增 `LedgerValuation.vue`，账户选择、手动刷新和写入成功后更新；缺少任一必要数据即总资产 null，已知小计单独标明。实际支持市场、错误码、预算和字段见[估值契约](../../backend/docs/ledger-api.md#当前股票估值)。70 项前端测试与后端检查/race/非真实来源 e2e 通过；真实 A 股、港股、沪市 B 股使用合成数量验证总资产，手机模拟视口无页面溢出。未部署。

“迁移”指数据库结构版本管理，不是导入用户的 Excel。

- `ledger.Open` 当前只有一份 fresh-install `001_init.sql`；没有已发布旧账本兼容、升级视图或双写路径。SQL 与校验和登记同事务，失败不留下半套结构；本轮不处理真实生产库。
- 复用现有数据库层的文件锁、WAL、外键、事务与迁移校验和。失败关闭句柄、释放文件锁，不接触 `liquor.db`。
- 本阶段按上述最新授权直接收敛 001；不承诺旧开发库兼容，也不绕过校验和或自动清库。
- SQL 使用 STRICT 表；数据库负责基础形状、外键、唯一性及类型检查，完整日历、现金合法性和成本计算由领域层负责。

| 表 | 职责 |
| --- | --- |
| `accounts` | 账户身份、本位币、期初日期、期初现金及版本 |
| `instruments` | 证券身份、市场与代码的唯一性、交易币种 |
| `opening_positions` | 期初数量、可选已知剩余成本及可选摊薄基数；未知与零不同 |
| `current_holdings` | 同账户手工当前现金与证券数量输入；整份替换、CAS、来源审计，不是历史资产或交易 |
| `operations` | 有类型的结构化操作、日期与日内顺序、成交/费用、已固定 FX 依据、状态、版本及幂等标识 |
| `account_records` | 唯一当前总资产/资金流/日志表；日期、稳定序号、signed flow、可空资产、来源、关联操作/来源审计、作废和版本 |
| `audit_log` | 唯一追加审计表；创建/修订前后值、原始导入、报价/持仓证据、沿用来源、账户/证券/期初持仓创建、周任务状态变更 |
| `idempotency_receipts` | 全局幂等键空间，保留规范请求、精确原响应和关联审计，不是修订历史 |
| `weekly_jobs` | 运行时任务状态；成功 history_id 关联自动估值或 `weekly_carry` 记录，并校验账户、日期和审计类型 |

```text
初始化导入 / 人工写入 / 持仓操作腿 / 当前及每周估值 / 每周沿用
                         |
                 同一个 SQLite 事务
                         |
       account_records + audit_log + 必要回执/任务状态
              |
       单账户列表 / 资产图 / 收益计算
```

fresh schema 不创建 `account_imports`、`imported_account_records`、`account_record_edits`、`account_record_revisions`、`operation_revisions`、`valuation_history`、`valuation_basis` 或 `account_record_order`，也不保留同名兼容视图。原始导入证据和所有历史版本只进入 `audit_log`；当前导入、人工、操作、自动估值和周沿用记录都在 `account_records`，不按日期/金额猜测去重。

相比之前的接口草案，当前不另建通用 `entries` 表，也不存派生 `positions` 缓存。一条转入并买入操作含独立转入金额和成交字段，领域计算输出不同语义的现金明细；一条转账关联双方。持仓、余额和周期从期初与有效操作重放得到，避免同时维护多份可能冲突的事实；将来确有性能需求再增加派生缓存。

## 3. 精度和金额含义

### T05 后端任务与来源（2026-09-07，全账户规则）

用户已确认周六 Asia/Shanghai 08:00，并进一步确认任务覆盖所有账户。`weekly.go`、`weekly_http.go` 和 fresh schema 复用 `valuationInputs` 的一致输入、水位与精确持仓计算；无自动来源时改走短事务，读取计划日以前最近有效的非沿用总资产。两条路径都无需伪造 HTTP 请求，原子写入记录、来源审计和成功状态。GET/HEAD 估值保持只读，真实估值 schema-1 字节格式不变。

- weekly_jobs 按 `(account_id,scheduled_business_date)` 唯一，保留 history_id。约束根据 `source` 核对 `weekly` 自动估值记录及 valuation 审计，或 `weekly_carry` 沿用记录及 carry 审计。成功保存总资产、冻结来源、任务状态与其审计在同一事务；失败状态实际落库时也审计，写库失败不能留下成功审计。
- `WeeklyWorker` 由 app 构造，在 `Application.Serve` 与白酒 worker 并行运行；构造无网络、无任务恢复写入。`LEDGER_WEEKLY_ENABLED=false` 默认关闭，关闭连恢复状态也不写；账本关闭不创建 ledger.db，同时配置周任务开启属于配置错误。固定时区随标准库 tzdata 嵌入，不依赖宿主机时区。仅 Go 测试可通过 Store 注入时钟，没有生产 fake-clock 环境变量。
- 启用后只在周六配置时刻至午夜处理当日任务。晚启动及当天新账户可补执行，不生成历史任务；跨日遗留任务过期，不拿当前价格回填周六。每轮新建/执行各最多 20 条，串行采样；轮次完成后等一分钟，临近下次计划时刻提前唤醒。已有全账本重放规模限制不在此轮解决。
- 单任务最多三次尝试，失败后 5/30 分钟退避，第三次终止。尝试状态先事务持久化；自动估值的网络在事务外，成功事务再次检查该账户持仓水位后是否有 `from_date<=as_of` 的相关变更，有则 basis_changed。沿用路径没有网络，在同一事务选择并冻结当前有效来源。无关账户、证券登记及其它账户记录写入不误触发自动估值水位。外部业务不共享 worker 的防重叠锁。
- 模块 DB 独占 lease 防跨进程竞争，同一 worker mutex 防并发 Tick；attempts + running 条件完成 fencing。重启恢复 running 为 failed/interrupted 并退避；无法清理的进程内 running 由 72 秒租约恢复。每次 12 秒估值预算，取消后的状态清理另有 3 秒预算；Serve 等待所有 worker 退出再由调用方 Close，构造失败关闭已有数据库。
- 仅完整现金/持仓/报价/最新 FX 及精确合计可保存。stock/FX 实际获取时间必须位于采样读取至计算完成之间、且不早于报价时间，FX 来源核对腾讯最新币对方向；不改旧快照的解释。提交准备前后检查北京时间当日窗口，跨午夜失败回滚。没有非零持仓时现金零也有效，不访问网络；缺任何必要持仓价格不保存小计。
- 无当前自动来源时，任务复制计划日以前最近一笔有效、非沿用总资产，写入 origin=`weekly_carry`、flow=NULL 的新记录，并冻结来源记录 ID、序号、版本、日期、金额及是否人工断言。后续周次仍指向最近明确来源，避免连续沿用把原始金额日期伪装得更新；人工修正后的沿用记录可成为新的明确来源。没有任何历史总资产时才 skipped/no_source。不改账户模式，不猜历史股数或现金，也不需要新增持仓转换接口。

配置和只读接口见 API 第 11 节。先前验证文档保留改动前的历史事实；本轮全账户沿用功能只完成定向测试，等待后续统一验收。没有修改 Python、生产配置或认证边界，没有读取真实账本。

人工创建、更正、作废直接更新 account_records，并向 audit_log 追加前后版本及原因；导入创建时即有版本 1 审计，不等首次更正才记录。回执先查询，再检查版本和当前状态；所有事务失败全回滚。关联操作的记录禁止普通编辑，返回 422 source_managed_record，须整体修正原操作，转账两腿一起变化。

手工创建 reported 账户不需要 Excel，不创建资产或现金事实。账户模式表示是否接受交易重放，不等同于当前估值能力，也不选择分析数据集。人工资产记录不会改变当前持仓现金；有效摘要覆盖所有当前记录，原导入摘要仅是审计参考。全日期摘要仍保留未来记录，分析另设截止日。

### T02 分析依据与失效追踪

T04 在该一致投影上附加纯计算 `calculateReturns`（returns.go），事务结束后只消费已有值，不重读资金流或行情。`returns.revision` 与图/明细相同；不新增迁移、缓存或写入。外层 T02 边界不变，收益对象单独标记 baseline/custom、请求日期、实际日终边界和来源。profit 用大整数分，Dietz 用有理数，XIRR 精确净额后才进入归一化浮点二分。端点 stale/untracked 阻止可信指标，carried/较早来源仅供参考；符号多次变化不声称唯一解。具体阈值、舍入及状态见 API 第 10 节与 T04 验证记录。

fresh schema 为所有来源直接分配同一全局稳定 sequence。导入保持来源行顺序，操作腿、人工记录、自动估值和周沿用均按成功写入顺序追加；更正保留原 sequence，不依据业务日期或 updated_at 重排。当前 payload、回执和历史版本统一由 account_records/audit_log 校验。

统一分析在一致事务内读取当前有效记录，按截止日过滤，同日资产为 post-flow。缺资产资金流逐条沿用前置资产原额，不加款，保留 reported/carried/unavailable 与来源 ID/version/date；过期或未追踪来源的状态也传递给沿用点。selected 优先当天最后明确总资产，不被后置资金流覆盖；无明确资产才取最后非日志记录。weekly_carry 未人工确认不算新观察，原行不变。期间 flow 含 [from,to]，净流入以 big.Int 合计。

失效水位直接来自 audit_log：账户记录改变更新统一分析 revision，持仓操作审计提供估值采样的 change_revision。报价过期只看相关持仓变更；更正改期取旧/新最早日期，不影响无关账户。审计变更范围不等于每日金额变化；原始操作追溯一律使用 audit_log。

估值输入在网络前捕获同账户持仓水位，保存在报价审计 metadata_json。分析只以它判断 provenance 状态，金额始终来自 account_records。人工修正自动金额时 manual_assertion=true，保留原报价引用但不再以旧报价为修正金额背书。作废不删除报价证据，成功周任务重试不复活作废金额。

GET analysis-basis 不接受 track，未知参数返回 400。单事务读取同账户全部有效 canonical rows，以最后明确资产优先的每日规则选点，资产是 post-flow。revision 是投影 SHA-256，since_revision 使用账户水位；超出 10,000 条事实/变更明确拒绝。T07 只消费该快照扩展收益曲线、TWR 和认证年化，无额外读库或网络，不回填历史行情。实现与待验收边界见 [T07 记录](../validation/2026-09-08-ledger-t07.md)。

## 4. 重放与业务规则

`Replay` 接收期初账户、证券清单、结构化操作和显式截止日期，不读取时钟、数据库或网络。按业务日期和唯一日内顺序排序，不修改调用方输入。未来日期、非法日历、重复操作 ID 或同日顺序冲突均拒绝；不得用录入时间猜实际成交顺序。

支持操作：外部转入、外部转出、买入、卖出、转入并买入、卖出并转出、指定周期的现金分红、同币种同日账户转账。

组合操作的金额字段仍是独立的外部现金流金额，不能默认为成交额；允许剩余现金。金额不匹配不是自动补造本金的理由。任何阶段出现现金不足、超卖、精度溢出或无效周期，返回包含冲突操作 ID 的错误且不返回部分账本结果。

日内先后由事务调用方明确提供，为全账本在该业务日期内唯一的正整数；反序提交只要业务顺序相同，重放结果必须一致。更正、作废通过替换有效操作或标记作废后完整重放验证，现已由 `Store.Write` 和默认关闭的本机 HTTP 接口提供能力，未在公网启用。

### 期初与成本

- 期初现金和持仓是当前持仓重放起点，不输出为新增外部入金，不设置历史来源切换日或桥接任务。
- 剩余成本与摊薄基数分别可未知。只有剩余成本，不足以推断经历过买卖及分红的历史摊薄基数；未知显示 null，不凭空填零。
- 新买入周期以首次买入操作 ID 标识；期初持仓周期由账户和证券生成稳定标识。分红必须明确归属周期，不能因晚到账而误摊到清仓后重买的新周期。
- 买入累加剩余成本；卖出结转成本并记录该周期已实现损益；分红不降低移动加权剩余成本。
- 本周期摊薄基数为起始已知摊薄基数加后续买入支出，减卖出净到账和归属该周期的到账分红。基数和单位摊薄成本允许为负。
- 清仓数量和剩余成本归零、单位成本返回 null；重新买入开始新周期。旧周期仍保留，允许后续分红明确归属旧周期。
- 账户收益率不由移动加权或摊薄成本计算，本阶段不提供收益率结果或伪造市值。

### 现金流与汇率

- 单个账户只有本位币现金余额。普通买卖和分红不增加外部投入，转入/转出与成交独立输出。
- 同币种转账双方同时变化，有共同操作身份，方便后续按汇总范围抵消；跨币种转账已明确不做，非等额转账继续不支持，不暗中选择差额规则。
- 本位币交易不需要 FX；外币交易或分红必须提供完整快照：正汇率、汇率日期、来源、获取时间，日期不能晚于业务日期。相同币种不接受任意 FX 改变金额。
- 汇率阶段新增 `fx.go` 的腾讯 provider 与 `/fx` GET/HEAD 查询：最新报价用于当前参考，历史按请求日向前 30 天查最近日收盘；六个 CNY/HKD/USD 方向，反向使用精确倒数。此前 Frankfurter/ECB 方案已被用户确认的腾讯主来源替代，不静默切换供应商。
- 查询先于写事务，返回来源、业务日期与获取时间；前端只将四字段 FXSnapshot 写入操作。已存交易不因查询刷新改变，编辑默认保留原快照。获取失败提示并允许手工填写；不新增数据库迁移或更改持久化 JSON 结构。
- 使用固定 HTTPS 上游、8 秒总超时、最多四个并发和 256 KiB 正文上限，禁止重定向。最新报价保留真实日期，历史缺失不以今天汇率补齐；自动汇率不等于股票市值估值已完成。

## 5. 已实现的本机接口

统一前缀为 `/api/platform/ledger`，默认关闭。完整请求体、分页、状态码及调用示例见[记账 HTTP 接口](../../backend/docs/ledger-api.md)。HTTP 使用独立 snake_case DTO，不改变已有数据库 Record/Operation 的 JSON，避免使历史修订和回执失效。

| 方法及相对路径 | 功能 |
| --- | --- |
| `POST /accounts`、`GET /accounts`、`GET /accounts/{id}` | 原子创建账户及期初现金/持仓、分页元信息、查询当前现金；未拆出可覆盖期初的 opening 路由 |
| `POST /instruments`、`GET /instruments` | 证券登记与分页查询 |
| `POST /operations`、`GET /operations` | 创建操作与按日期、账户、状态分页查询 |
| `POST /accounts/{id}/operations`、`GET /accounts/{id}/operations` | 固定账户范围的创建/查询入口 |
| `GET /accounts/{id}/positions` | 查询持仓与两种成本，不把成本当行情 |
| `POST /transfers` | 关联双方的同日转账 |
| `GET /operations/{id}`、`PUT /operations/{id}`、`DELETE /operations/{id}` | 详情、更正和作废，不物理删历史 |
| `GET /operations/{id}/revisions` | 修订版本升序分页 |

写操作用 `Idempotency-Key`，更正/作废 body 使用字符串 `expected_version`。操作 ID 和日内序号由调用方稳定提供，同一请求重试不重新生成。请求最多 64 KiB，列表 1..100 条；未知、重复或 Unicode 别名字段拒绝。成功金额、股数、价格、汇率及版本/序号使用字符串，HEAD 不返回正文。

服务层须在同一个 `sql.Tx` 内进行版本/幂等校验、操作与修订保存、历史重放验证及提交。重复同键同内容返回同结果，不同内容冲突；所有事务读取使用 `tx`，避免单连接池内递归占用连接。外部汇率获取在写事务之前完成。

账户本位币和证券交易币种属于历史金额的解释依据，未来服务不能允许普通编辑直接更换币种并重新解释全部旧记录；币种迁移需单独设计。

`NewStore(db, now)` 接收已由 `ledger.Open` 打开的数据库；不拥有关闭职责。`now` 可注入测试时钟，传 nil 使用系统时间。业务日期截止按北京时间当天计算，创建和修订时间保存为 UTC。

| Go 方法 | 当前行为 |
| --- | --- |
| `AddInstrument(ctx, instrument)` | 新增证券；同 ID 且全部字段相同的重试无副作用；已有 ID 的不同内容或重复市场代码冲突，不改写历史币种 |
| `InitializeAccount(ctx, name, opening)` | 一个事务初始化账户、期初现金和全部期初持仓；同账户 ID 再初始化报冲突，不覆盖已建账状态 |
| `Write(ctx, Command)` | 统一创建、更正、作废，返回本次提交的 `Record` |
| `GetOperation(ctx, id)` | 读取当前已提交版本，包括已作废记录 |

### 写入命令

| 字段 | 含义 |
| --- | --- |
| `Action` | `create`、`replace` 或 `void` |
| `Key` | 此次写请求的幂等键；跨创建、更正、作废全局唯一，使用新键表达新意图 |
| `Operation` | 创建、更正传完整结构化操作；作废仅传操作 ID |
| `ExpectedVersion` | 创建为 0；更正和作废必须等于当前版本 |
| `Note` | 操作备注，最长 8192 字节；作废不传新备注，保留原备注 |
| `Reason` | 必填的创建、更正或作废原因，随修订保留 |

操作和幂等键由调用方提供稳定标识，ASCII 字母、数字、下划线或连字符，最多 128 字节；HTTP 层未来可以在此约束上设计 ID 生成和请求适配，不应在重试时重新生成 ID、顺序或汇率快照。

`Record` 保存完整 `Operation`、备注、版本、创建时间和更新时间。首版为 1，每次成功更正或作废加 1；原始创建时间不变。作废保留原字段和日内顺序，只改变作废状态，不能用 replace 恢复已作废记录。恢复流程不在当前范围。

### 幂等与并发

1. 对带类型的完整命令序列化，计算 SHA-256 请求摘要，包括 Action、预期版本、备注、原因及固定 FX 快照；未填写费用与显式零是不同输入。
2. 开启 immediate SQLite 事务，先查回执。同键不同摘要返回 `ErrIdempotency`；同键同摘要返回该次成功时的原始 Record，而不是当前最新版本。
3. 未命中回执时加载完整期初和全部操作，检查身份、当前版本及状态，在内存中应用变更并重放全历史。
4. 验证通过后保存当前操作、对应完整修订和幂等回执，一起提交。UPDATE 再次使用版本和 active 状态条件，防止丢失更新。
5. 任一步失败均返回空结果并回滚；失败不会占用幂等键。超时结果不确定时，重试同键同命令可判断先前是否提交。

旧创建请求在操作后来更正或作废之后仍返回旧创建版本；要查看当前状态须调用 `GetOperation`。跨进程重开数据库后回执仍有效，不依赖内存缓存。保留回执不等于再次执行旧操作。

组合转入买入和同日转账都作为一条完整操作保存；不能只更正、作废一条转账腿。重放覆盖所有账户、全部日期的后续操作，不能为了让某条修改成功而忽略后续超卖、透支或周期冲突。

### 初始化、错误与完整性

- 当前期初初始化是一次性的，不支持覆盖或更正；已有账户的 `version` 仅是保留字段，不作为操作更正 CAS。未来期初更正须单独设计，不绕开历史校验。
- 期初未知成本、未知摊薄基数、未录入费用使用 SQL NULL；金额及 FX 按整数尺度往返，不用浮点。
- `ErrVersion` 区分并发版本冲突，`ErrVoided` 拒绝继续修改作废操作，`ErrNotFound` 表示操作不存在，`ErrConflict` 表示身份或唯一性冲突；历史余额/持仓失败保留 `OperationError` 的冲突操作 ID 和日期。
- 读取当前操作时核对 SQL 字段与当前完整修订，回执核对其对应版本的修订；缺失或不一致返回 `ErrCorrupt`，不能因关联缺失而静默漏掉一条资金记录。修订内容是本程序写入的固定 JSON 形状，未来改结构需考虑持久化版本兼容。
- 拒绝非法 UTF-8 文本，避免 SQL 字段和 JSON 替换编码后出现无法读取的已提交记录；约束错误不返回触发器携带的私有原值。
- 这一层面向受信任调用者，不提供用户身份隔离。数据库持有人能直接执行 SQL；上述一致性校验不是防管理员篡改的签名或不可变审计系统。HTTP 当前限制在本机，不能因返回 JSON 就认为已具备用户授权。
- 当前采用全账本重放，一次写入读取并验证全部历史；账户状态查询也使用一致事务。列表已有有界分页，但没有增量重算或大规模性能容量保证。多页查询不是冻结快照，更正日期/顺序期间翻页需客户端刷新。

## 7. 安全和验证

本轮源码把 Nginx/Vite 的服务令牌代理收窄为 `/api/platform/liquor/`，Nginx 其余 `/api/platform/*` 返回 JSON 404，未部署此变更。app 在 `LEDGER_ENABLED=true` 时打开并关闭独立账本库；必须回环监听，并检查实际 socket peer，转发头不能授予访问。保留既有 token、Host 和跨站写保护，默认不建账本库。

随后网页阶段为 Vite 增加显式开启的开发代理例外，仅 `/api/platform/ledger` 前缀可转发，后端目标、实际 socket peer 和 Host 必须本机，并拒绝跨源请求。此插件仅用于开发，不进入生产 Nginx 或浏览器构建。未移除任何后端保护。

当前代码禁止非回环监听，即使有 token 也不能直接开启生产 Compose 的账本功能，不应绕过既有边界临时暴露接口。新一期目标允许无真实数据的公网免登录展示，不先开发完整身份系统；公网入口与匿名读写范围须显式设计，不修改其他模块的令牌保护。真实私有账本接入前仍需适当访问控制和 HTTPS/VPN 等保护，此要求不因演示阶段免登录而取消。
