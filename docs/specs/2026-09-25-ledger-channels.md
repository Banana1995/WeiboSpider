# 投资账户内的渠道记账

## 语义与参考

- 投资记账账户按目标组织；渠道是这个账户内部的平台、策略或产品分组。交易所账户、券商账户和钱包都可以用作渠道。
- 官方说明：[渠道有什么用](https://youzhiyouxing.cn/n/lite-posts/167?format=md)、[记账使用指南](https://youzhiyouxing.cn/n/materials/1408?format=md)。官方把渠道称为求和的辅助工具，既不要求每个渠道都是独立物理账户，也不把渠道当作证券持仓明细。
- 转入转出的边界是整个投资记账账户。同一账户内部的渠道间调拨，通过更新渠道资产记录；只有跨过账户边界的资金才作为外部资金流。渠道标签不增加第二笔资金流。

## 交互规则

1. 转入 / 转出：没有渠道时隐藏渠道选择；有渠道时展示已有渠道的选择框，默认第一个渠道，支持改选。
2. 更新总资产：没有渠道时显示单个总额输入框；有渠道时自动展开各渠道，并显示上次记录的金额和日期。
3. 上次金额作为参考展示，新金额保持空白。用户可以逐项填写，或主动点击「填入上次金额」后修改；所有渠道填写完整后以精确金额求和。
4. 可在资产表单添加渠道。渠道名称可调整，移除的渠道不进入本次快照；历史记录仍保留原名称和金额。单次快照最多 100 个渠道，名称唯一、非空、最多 128 UTF-8 字节，金额非负、最多两位小数。
5. 转入转出可选「同时更新总资产」，把资金流及变动后的渠道资产保存为同一笔记录。记录详情和修改历史展示渠道金额，列表展示资金渠道或渠道数量。

## 导入与兼容

- Excel G 列「明细」的每行 `渠道名称：金额`（也支持半角冒号、CR/LF 换行）解析为渠道资产快照。所有渠道金额之和须与 D 列总资产精确一致。
- G 列既可出现在资产行，也可出现在带总资产的转入转出行。后者仍然只创建一笔混合记录。
- 空 G 列不生成渠道；零金额保留。不能完整解析、重名、超限或合计不一致时保留原始明细及原总额，不进行部分拆分、补零或修改总额。预览响应通过 `channels.unresolved_rows` 给出原行号，记录详情仍可核对原文。
- G 列表示该次记录的资产组成，不能据此反推这笔资金流的渠道；旧文件导入的 `flow_channel` 保持缺失。用户后续手工记账可选择渠道。
- 新导入把渠道快照保存在正式记录中；已有、未更正的导入记录可在读取时由 `original.detail` 恢复渠道。旧审计字节、幂等回执及导入 digest 不改写，不要求重导文件。已更正为仅总额的记录不回填旧明细。
- 金额继续按账户币种保存，不把渠道名称解释为币种、证券代码或持仓。

## 数据接口

账户记录 `AccountEntry` 新增可选字段：

```json
{
  "channel_assets": [
    { "name": "示例平台", "amount": "100.01" },
    { "name": "示例钱包", "amount": "0.00" }
  ],
  "flow_channel": "示例平台"
}
```

- `channel_assets` 是完整快照，必须与 `total_assets` 相加吻合。`flow_channel` 只允许用于包含资金流的记录。
- 记录仍通过既有创建 / 编辑 / 作废接口保存，沿用版本号、幂等和审计事务；不新增独立账户，不改变收益计算的总额与现金流入口。
- `GET /api/platform/ledger/accounts/{id}/channels?to=YYYY-MM-DD` 返回指定日期之前最近有效的渠道快照及来源记录 / 日期。缺省日期为北京时间今天；同日按正式记录顺序选择，不使用作废记录。
- 响应 `items` 按来源快照顺序提供 `{name, amount}`；`source_record_id`、`source_date` 说明上次观测来源。没有快照时 `items` 为空，两项来源为空字符串。
- 后续资金流或仅总额记录不推算各渠道余额；界面把快照金额标为「上次」并显示其实际日期。编辑历史记录保留其自身的渠道快照。

## 验证范围

使用合成工作簿与本地临时数据库验证完整导入、混合行、同日顺序、精确求和、原始明细保留、旧审计兼容、重复导入、修改历史与作废；前端验证默认渠道、无渠道单总额、有渠道逐项金额及零金额、混合行编辑和读取失败重试。真实用户工作簿不放入仓库或测试夹具。
