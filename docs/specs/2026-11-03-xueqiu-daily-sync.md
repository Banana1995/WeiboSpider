# 雪球每日增量与时间修复

## 调度与评论范围

- 跟随现有“启用定时抓取”开关，每天 **Asia/Shanghai 21:00** 执行一次 `xueqiu_crawl`。重启不会立即抓取；错过关机期间的运行，等下一天。
- 顺序为增量帖子入库 → 评论目标查询 → 评论抓取。手动“雪球增量”复用该流程；“雪球抓取”仍只全量帖子。
- 同一雪球流水线互斥，避免手动和定时任务重叠。帖子失败或取消，不继续启动评论；操作日志记录每日任务结果。
- 评论包含最近 **48 小时**的非删除雪球帖子（不限 PS 图），以及 `xueqiu_comment_queue` 中待补的帖子。新入库帖子与队列在同一事务写入；评论成功（含有效空结果）后才出队，失败、取消、重启后仍可补抓较旧帖子。
- 每帖按上游热度取前 100 条一级评论及其回复。增量按评论 ID 更新，保留已有历史评论；不把重复处理的评论计为新增。手动 PS 图/单帖刷新沿用热榜替换规则。
- 请求失败、非 JSON、业务错误、异常结构或分页不完整均报告失败，不以空结果冒充成功。

## 去重与增量检查点

- 帖子主键为 `xq` + 原帖 ID，评论主键为 `xc` + 原评论 ID。全量重抓会更新原记录，不会复制帖子、评论或搜索文档。收藏、笔记、手动 PS 标记及删除状态保留。
- 帖子结果分别显示 `new` / `updated`。旧日志的“新增”实际上是处理次数，不能据此判断数据重复。
- `xq_timeline_checkpoint_<user_id>` 仅在成功抓完本轮后推进；分页中途失败，下次仍从旧检查点重试。检查点按源 ID 而非旧库发布时间排序，避免时区修复影响边界。
- 跳过页首旧置顶帖后继续处理当前页；页尾到达检查点才结束分页。

## 时区及历史修复

- 雪球 `created_at` 为毫秒 Unix 时间戳。原代码 `datetime.fromtimestamp()` 未传时区，线上 UTC 容器因此保存了 UTC 墙上时间，前端却直接当作北京时间展示。
- 新帖子和评论显式转换为 UTC+8，并标记 `created_at_timezone='Asia/Shanghai'`。已有帖子重抓时也能用上游原始时间修正；微博时间不受影响。
- **不在应用启动时对所有数据库自动加 8 小时**。本地或导入库可能原本就是北京时间，需要先确认历史写入环境并对照上游时间戳。
- 显式工具 `weibospider/repair_xueqiu_timezone.py` 仅处理未标记的旧雪球记录，事务更新帖子与评论。运行后带标记，再执行不会重复平移，新版重抓已修复的记录也会跳过。无效时间会整体回滚。
- 预览（会初始化缺失的表/列，但不修改时间）：

```bash
python repair_xueqiu_timezone.py --db /path/to/data.db --legacy-timezone UTC
```

- 核验旧库确实为 UTC 后应用，必须提供不存在的备份路径：

```bash
python repair_xueqiu_timezone.py --db /path/to/data.db \
  --legacy-timezone UTC --apply --backup /private/backups/before-xueqiu-time.db
```

- 备份通过 SQLite backup API 生成，文件权限 0600，含 Cookie 等私有数据，禁止提交。原本正确的北京时间旧库使用 `--legacy-timezone Asia/Shanghai`，只标记不平移；混合来源库不能直接用单一时区批量修复。
