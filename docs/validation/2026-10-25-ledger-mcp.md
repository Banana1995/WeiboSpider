## 关键场景与证据

### 1. 金融输入和历史规则

`mcp_commands_test.go`、`mcp_business_test.go` 覆盖：

- 买入、加仓、卖出、手续费、分数股精确舍入、清仓与新周期成本。
- 字符串数值规范化；负数、负零、科学计数、逗号、超精度及溢出拒绝。
- 日期和币种错误拒绝。
- 更正旧证券流水时也校验当前支持的市场／币种范围，避免产生无法按契约恢复的回执。
- 无现金基准与显式零余额区分。
- 基准日前交易不重复扣减、现金不足拒绝。
- 跨币种 FX 缺失、明确结算及历史已覆盖规则。
- 初始持仓补录数量只计一次，未知成本恢复为确定成本。
- 历史更正导致后续超卖时完整回滚，错误包含失败流水 ID。
- 作废保留历史，查询按 include_voided 展示。
- 自动分红冲突返回原流水；实际到账更正和作废不被 worker 恢复。
- 更正权益日数量时，回执包含同事务自动分红变化与实际现金差额。

### 2. 幂等、并发与不确定结果

- 相同业务键、等值规范化参数只提交一次。
- 旧请求在当前版本提高后仍返回原回执。
- 不同内容或跨写工具重用业务键报冲突。
- 相同 request_id 在不同账户独立提交，回执和流水身份不同。
- 两个并发相同请求恢复相同提交；不同请求竞争同一版本仅一个成功。
- MCP 交易与分红 worker 并发后现金符合胜出顺序，分红只结算一次。
- 事务成功后丢弃完整协议响应，再查询／重试可恢复。
- 首次外部解析仍在执行时，回执查询返回 not_found、definitive=false；原请求之后可成功提交。
- 数据库关闭再打开后，MCP 回执仍可恢复；现金余额请求跨日恢复也不重新记账。

### 3. 原子提交与证据完整性

通过合成 SQLite 拒绝触发器分别让证券、交易、journal、持仓、命令审计或回执插入失败，验证没有残留的部分证券／交易或审计。

从 001..007 的数据库升级到 008，验证旧请求、响应、摘要逐字节一致；原 REST WriteStock 仍能返回旧回执。再次打开数据库不重跑迁移，外键检查通过，回执 UPDATE 仍被拒绝。

在隔离测试库中主动移除测试所需触发器并破坏回执摘要、审计关联或响应金额，读取和重试都返回 data_integrity。已删除账户的历史回执遵循原有不可访问规则。

### 4. 查询、分页与外部来源

- 账户先筛选再分页，名称包含 `%`／`_` 时按字面匹配。
- 流水日期与 sequence 排序，跨页无重复／漏项。
- 日期过滤、精确 entry_id、作废过滤和默认摘要查询。
- 账户版本、业务日或筛选变化时拒绝旧游标。
- 查询不新增审计，不依赖行情提供方。
- 新证券来源离线／身份歧义不会部分创建证券或交易。
- 已有证券目录在离线条件下仍可搜索和记账。
- provider 测试会在解析过程中读取同一个单连接数据库，证明外部解析不在记账事务内。

### 5. 协议、Schema 与访问边界

使用官方 SDK 客户端连接真实 httptest HTTP server，列举并调用全部八工具，验证 structuredContent 与文本 JSON 一致。另以原始请求验证 2025-11-25 initialize 及无会话 ID 行为。

覆盖未知字段、大小写字段、非法分页上限、JSON number 金融数值、重复 JSON 键、多个顶层对象、超大请求、非法 Origin、GET/DELETE 405，以及账本 MCP 开关、非法配置和其他模块的令牌保护。

实现过程中发现 SDK Schema 推导不识别 Go `json:",string"` 的 sequence 编码，已显式为输出 sequence 配置字符串 Schema；完整 SDK 调用链验证了修正后的输出。

- Compose 配置开启 MCP，既有账本 Nginx 子路径可直接转发；本次没有改写其他工作的 `/mcp` 代理。

- 008 升级后的优先回退方式是关闭 MCP，并保留了解 008 的兼容程序。
- 仓库内文档、测试夹具和示例均使用合成数据。
- 发布仍需遵循仓库的提交／推送／部署授权和共同部署流程；生产验收采用健康检查、初始化、工具列表及读工具。
