# 投资账本 MCP 评审：持仓与账户资金流

下文保留 1.4.0 时的评审基线和决策。**实施结果（1.5.0）**：已新增查询、创建及更正账户资金流水三个工具，共用网页的账户记录事务；持仓及账户资金回执均可按原请求查询。实际参数、版本与示例见[接入指南](../guides/ledger-mcp.md#账户资金流水)。导入回单取舍及业务行移除见[账本 Excel 导入设计](ledger-excel-import-design.md)。

## 能力缺口

| 业务事实 | 当前实现 | 对 MCP 的建议 |
| --- | --- | --- |
| 某只证券买入、卖出、分红、扣红利税 | MCP 已支持，写入单股流水，可按证券及渠道查历史 | 保留现有行为。卖出不自动记一笔账户转出。 |
| 钱从账户外转入或转到外部 | 网页通过账户记录服务写入 `cash_flow`，收益分析使用这些记录；MCP 缺少相应的读写工具 | 增加按账户列出、定位资金记录，以及记录转入、转出和更正的能力。 |
| 某日实际剩余现金 | MCP 可以设置余额基准 | 余额是一个时点的金额，不能代替转入、转出。 |

**为什么不能直接复用现有持仓工具：** `ledger_edit_entry` 的目标是持仓流水 ID，校验整本持仓的版本。账户记录有自己的记录 ID、来源和单条记录版本。`ledger_get_write_result` 当前解析的也是持仓写入回执。参见 [MCP 工具注册](../../backend/internal/modules/ledger/mcp_tools.go)、[回执校验](../../backend/internal/modules/ledger/mcp_receipts.go) 和[账户记录服务](../../backend/internal/modules/ledger/account_records.go)。

## 建议的账户资金流操作

- 查询：按账户、日期和状态分页；可按记录 ID 读取金额、方向、币种、备注、来源及当前版本。先区分手工、Excel 导入和系统产生的记录，再更正目标。
- 新增：取得准确账户，明确业务日期、转入/转出和正数金额；币种以账户币种为准。转入写正流水、转出写负流水。缺少确定金额或折算结果时补问，不把证券成交金额推算为出入金。
- 更正：复用网页的 `WriteAccountRecord` 规则，带目标记录版本和原因；保留未修改的渠道、可选总资产和原始导入证据。不要用持仓版本或账户资料版本代替记录版本。
- 重试与核对：同一业务请求沿用同一 `request_id`、只入账一次；回执应能区分账户和持仓操作。写入后可读回有效记录、净流入和收益；账户流水不应重复改变持股数量、现金基准或生成第二笔资金记录。

例如，“卖出 100 股，钱留在券商账户”只记卖出；“从账户转出 800 元到银行卡”只记 800 元转出。如果两件事都发生了，应分别记录成交金额和**实际转出**金额，两者不必相等。不能根据卖出时间和金额自动补一条账户转出。

验收时验证三件事：同一转出请求发送两次只产生一条资金记录，余额基准及股数不因此被改写；按原记录版本改备注后，仍可定位同一条流水并读到原因；用过期版本更正时明确提示冲突，不新增或覆盖另一笔。导入来源、原始凭据和没有被用户修改的字段应保留。

## 单笔物理删除是独立的存储问题

现有账户记录 `DELETE` 的业务含义是作废。对仍存在的账户，数据库不允许直接移除其中一条记录。[导入历史校验](../../backend/internal/modules/ledger/import_history.go)逐项核对批次清单、原始行和对应的账本记录；若业务行缺失，后续导入摘要及增量导入会因证据不完整而报错。备份本身解决不了这一约束。

如果要求“从账户记录中移除，连已作废列表也不留”，可以保持网页和 MCP 接口不变，另做存储维护：让原始导入凭据独立于有效业务行，保留删除原因、对应来源和去重信息。维护前应在隔离库证明：清理只影响选定记录、旧文件重导不会复活、后续增量可以追加、旧回执仍可核验、有效转入转出和收益均与预期一致。不能把现有的作废操作称为物理删除。

本次在临时数据库运行了 `TestSchemaCoreConstraintsAndAppendOnlyHistory` 与 `TestIncrementalImportFromLegacyAccount`；两项通过。这验证的是当前约束与导入行为，不代表已经支持或执行单条硬删除。
