# 卖 Call 视图验收（2026-11-16）

## 功能与口径

- 正式 `/options` 新增卖 Put／卖 Call 切换；Call 按备兑策略展示，每份对应 100 股，默认取 Bid 估算卖出收入。
- Call 按股票快照参考市值计算权利金收入率和单利年化；行权价对应金额单列为被指派时股票卖出金额。切换净投入时扣除本次权利金收入，不冒充裸卖保证金。
- Call 价内外及内在价值方向与 Put 相反。详情包括备兑所需股数、含权利金卖出价、持股参考成本及独立到期／平仓情景。
- 持股成本未填写时，仅计算期权部分；填写明确成本假设后才展示持股＋卖 Call 的合计情景盈亏，主表权利金年化不随情景变化。
- Call 可用行权价下限、含权利金卖出价下限、天数、年化、OI、成交量、价差、Delta 等筛选。每股条件与默认方案按类型分别保存。
- 比较、手机卡片、任务提示、历史摘要、收藏列表和冻结详情均显示准确的 Put／Call 类型。切换类型清空临时条件和比较选择，只读缓存。

## 数据与兼容

迁移 `004_option_sides.sql` 将原目录、latest 和每日摘要归为 PUT，再改为股票＋类型联合键；快照追加类型列。原始快照和收藏 JSON 不改写，旧 Put 任务回执继续重放。

本机升级前使用 SQLite 一致性备份。对原有 1 条收藏、3 份快照的原始 JSON 做 SHA-256 核对，升级后完全一致，自选仍为 2 只。备份及校验清单位于仓库外私有会话目录。

API 的 `option_type` 仅接受 PUT／CALL，省略时默认 PUT。相同请求编号跨类型使用返回冲突；运行中的 Put 任务不会被当成 Call 任务合并。Call 目录和报价返回的类型必须与请求匹配，错型拒绝发布。

- 全额口径年化36.500000%，净投入口径37.628866%。

- 两份合约、开仓费5时净收入595，备兑股数200，含权利金卖出价112.975／股；费用不改变毛权利金的内在／时间价值拆分。
- 54组独立“买入股票现金＋卖期权收入＋到期交付／股票市值”模型，与备兑到期公式一致。
- 缺少正股价格时不伪造 Call 市值／年化；缺少持股成本时不伪造合计收益。

### 浏览器流程

- Put 切至首次无缓存 Call、刷新页面、改变筛选均不增加报价请求；只有点击更新才抓取 CALL。
- Call 更新后原 Put 快照 ID 不变；两类目录独立缓存，历史分别保留。
- Call 价外筛选只留下 K>S 的样本；资金列显示21,000股票市值，而不是22,000行权金额。
- 两份、自定义费用、到期股价及持股成本测算：期权部分−5,405，持股＋Call合计4,595。
- Call 自定义收藏冻结所有参数和结果；更新 Call、切回 Put、重启 Go 后仍保持原内容。
- 手机390px页面及详情无横向溢出；Call 更新失败保留两边的最后成功快照。
- 原 Put 收藏及旧请求回执不受类型升级影响。
