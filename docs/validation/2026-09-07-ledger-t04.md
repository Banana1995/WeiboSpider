日期：2026-09-07。范围：累计收益、Modified Dietz、XIRR 及同快照页面展示。设计已先说明再实施；独立复核发现的舍入问题已修复并再次复核通过，路线图标记完成。未提交、推送、部署或处理真实财务附件；未实现 T05 及后续任务。

## 实现

- 复用 GET/HEAD analysis-basis，新增 returns 对象而非第二个收益/资金流请求。图、指标、端点和计算明细对应同一个 revision。计算在事务所得不可变投影上执行，不重读行情或账本、不写估值、不新增迁移。
- 金额净流量和利润用任意精度整数分；日数为公历整数差；Dietz 权重/分母用有理数；仅 XIRR 数值求解使用浮点。百分数直接从未舍入结果 half-away 舍入，避免十二位比率再转百分数的双重舍入。
- 默认以首个已知日终资产为基准，排除该日资金流；明确 from 时取此前最后资产并使用前一日日终边界。最终截止为实际资产/沿用记录，不延伸空白到今天。reported 沿用原额只供参考；holdings 最后观察之后还有资金流则缺期末，不静默漏算。
- 缺期初/期末、非正区间、过期/未追踪端点、非正 Dietz 分母、XIRR 无解/全零/可能多解/范围不足/未收敛分开说明。普通买卖、组合交易的成交部分、留存分红不重复当外部投入。
- 一次符号变化保证唯一根；多次变号只标可能多解，不宣称已证明多根。XIRR 的两笔 365 天路径使用精确有理数；一般路径有固定范围与轮数、残差/精度守卫、独立舍入区间认证和 context 取消检查。独立复核发现的数学中点舍入问题已复现、修复并复审通过，证据见下方记录。详细数值限制见 [API 第 10 节](../../backend/docs/ledger-api.md#10-同快照收益t042026-09-07)。
- Vue 展示三张卡、各自状态、请求/实际日期、来源版本与采样时间、每笔流量权重、投资者同日净额；详情每页 30 条。校验请求身份和同快照 revision，切换账户/轨道/日期清除并取消旧读，不动已有导入或写入锁。

## 独立复核 P2 修复

2026-09-07 独立复核发现：一般浮点根即使残差和区间宽度达标，转换为 Rat 后按 half-away 舍入，也不代表对数学真值正确舍入。原实现把 365 天、整数分 `[-20000,20001]` 与 `[-20000,19999]` 的年化数学真值 `±0.00005` 均显示成 `0.00%`。

先增加 `TestXIRRExactAnnualHalfAwayRegression`，在修改求解器之前运行，两个子例均失败：日志分别记录 `value=0.000050000000 percentage=0.00` 与 `value=-0.000050000000 percentage=0.00`，预期为 `0.01` 与 `-0.01`。没有将失败归因于测试误差或直接改变断言。

修复阶段只改六个文件：`returns.go`、`returns_test.go`、`frontend/src/ledgerReturns.ts`、`frontend/src/LedgerReturns.test.ts`、API 文档及本验收文档；该阶段先保持进行中，再次独立复核通过后更新完成状态。

- 两笔非零现金流相隔恰好 365 天，公式是线性的，直接返回精确有理数。数学中点的正负 half-away 均正确，value 和 percentage 仍分别从计算值舍入，不二次舍入。
- 一般浮点搜索只提供候选；对十二位比率和两位百分数的舍入区间交集，以 192 位有向舍入运算独立计算 NPV 符号包围。通过变换为每日折现因子 q 的整数日幂多项式，不需要对 exp/log 的浮点实现假定固定 ULP 误差。只有真实唯一根严格位于交集内部才显示；无法证明时 precision_unresolved，不采用固定 epsilon 或任意根一侧。
- 认证预算有界：每端点最多 192 次 q 区间二分，每个现金流用整数平方求幂，精度固定 192 位，保留 10,002 日期容量与取消检查。不添加第三方依赖或完整符号求根库。

最终针对性 Go 实测：

| 输入（除特别说明外为整数分） | 结果 |
| --- | --- |
| 365 天 `[-20000,20001]` | value `0.000050000000`，percentage `0.01` |
| 365 天 `[-20000,19999]` | value `-0.000050000000`，percentage `-0.01` |
| 730 天 `[-400000000,400040001]` | 真实年化 `+0.00005`；precision_unresolved，两个输出 null |
| 730 天 `[-400000000,399960001]` | 真实年化 `-0.00005`；precision_unresolved，两个输出 null |
| 730 天上述终值各 ±1 分 | 正确区分中点两侧的 `0.00` / `0.01` 或 `-0.01`，不强行向中点靠拢 |
| 三笔现金流、第 0/365/730 天 `[-20000,1,20001]` 及 `[-20000,-1,19999]` | 真正的百分数中点，precision_unresolved |
| 第 0/365/730 天 `[-2000000000000,1,2000000000001]` 及负向对应值 | 真正的十二位比率中点 `±0.0000000000005`，precision_unresolved |
| 第 0/180/365 天，金额 `-1000,+500,+600` | value `0.132563787072`、percentage `13.26`；所有现金流乘 `10^13` 仍完全相同 |
| 人为从真值两侧给出错误浮点候选括区 | 独立舍入认证均拒绝，不能依赖浮点括区的错误信心 |
| 距真实百分数中点仅 `±1e-18` 的精确比率边界 | NPV 符号正确认证；现金流再乘 `10^10` 结果不变 |
| 365/730 天，初值接近 int64 上限、终值 1 分 | 保留负收益及接近 -100% 的正确舍入，不溢出或误判为正收益 |
