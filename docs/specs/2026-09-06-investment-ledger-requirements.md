- **U31：最多一张 audit_log，所有已提交业务操作同事务审计。** 创建、修订、初始化、报价/持仓证据和任务状态均可追溯，不保留其他可写历史存储。
- **U32（独立复核后澄清，覆盖 R29 的旧 GET 行为）：估值 GET/HEAD 必须只读。** 页面浏览不能压过人工金额；明确 POST 才重新计算并保存，原键重试返回经过历史审计验证的原回执，不重新获取行情或恢复旧金额。当前 fresh schema 直接以统一 account_records/audit_log 保存所有来源，不保留旧迁移兼容层；更正不使用修订时间重排，也不设置切换日期。
- 每周六 Asia/Shanghai 08:00，默认关闭；前端仅只读状态和历史，不提供启用/重试操作。任务覆盖所有账户：有当前持仓来源时自动估值，无自动来源时复制截至计划日最近一笔有效总资产并明确标记沿用；没有历史总资产才不更新。沿用不冒充现金、持仓或新行情，也不要求给既有账户补建持仓。
- 用户明确历史导入的总资产、转入和转出记录足以作为历史收益及图表的数据输入；不要求补全历史证券交易或持仓。分红、拆股、送股的历史影响已在总资产中，不回溯、不另外叠加。
- “估值”在产品层面就是取得并保存一笔总资产记录；自动用行情计算只是记录金额的一种来源，不是历史收益计算的必备步骤。文档优先称“总资产记录”，已有代码/API 名称不在本轮改动。
- 每周六只更新总资产记录，取消独立事件日前后采集任务及 T06 历史行情回填/资产重建。记录更正后依据有效金额和资金流重新计算收益仍然保留，不通过历史股价重新计算导入金额。
- 跨币种转账、增量导入、不同版本合并、批次撤销不做；已有单批次导入、幂等重试、逐条维护、手工分红、同币种转账和交易/持仓汇率折算保留。
- 目标相关保留目标规划、预期曲线；目标提醒、通知和分享暂不做。未来自动分红等复杂金融事件不作为本轮待办或分析前置。
- TWR 和曲线直接消费资产及资金流记录，继续遵循以下日期、同日顺序和沿用规则。无起点或零分母等数学边界仍应明确提示，但不以历史行情回填阻塞开发。真实附件落库验收与是否需要证券历史回填是不同事项，前者尚未执行。

### T02 最新确认（优先于下文历史讨论中的未决表述）

- 同行总资产是该行资金进出之后的金额，不重复加款。
- 2026-09-08 确认修正：每日选最后明确非空总资产，不被后置资金流行覆盖，资产已含当日进出，不重复加款；无明确资产时才取最后非日志沿用/缺值依据。weekly_carry 不是新观察，人工确认除外。逐条明细仍按日期和稳定序号保留，导入来源行和原金额不变；更正或改日期保留序号，不隐式重排。首行明确总资产且没有资金流是有效基准，不虚构初始入金。
- 未填总资产的资金流，在分析中沿用按日期和稳定序号排列的最近前置有效资产原值，**不加本笔或累计现金流**。补记不能取未来日期或同日更后序号；首次无资产则 unavailable，零是有效值。返回 carried 和明确资产来源的记录 ID、版本、日期；这种分析期内的隐式沿用不写库。T05 经用户另行确认，会显式保存一条带 `weekly_carry` 来源的新周记录，两者不能混称新行情观察。
- 以上规则统一用于同账户的所有当前有效记录。来源仅用于追溯和可信状态，不筛选业务数据。结构化操作每个账户腿只生成一条资金流或日志；普通买卖及留存分红 flow=NULL，不能从操作详情再计一次流入。R14 的跨账户汇总规则不能替代单账户缺值沿用。
- 分析默认截止北京时间今天，显式 to 不能在未来；未来日期仍可存为原始记录，但不倒填当前或历史分析。区间 [from,to] 的资金流含首尾日，opening 为 from 之前最后有效依据，closing 为 to 及之前最后依据；无期初不能用零或伪造入金填补。T04 的默认收益基准、实际截止、日权重和求解细化见第 5.4 节，不改写上述原始分析依据。
- 公网匿名共享全部读写已明确，不再询问只读/隔离演示选择，不加认证。发布路由、资源限制及防跨站策略仍在 G02 发布准备中验证；本次不改运行保护，不处理真实账本。

架构约束见[多数据源平台整体架构说明](2026-09-05-multi-source-architecture.md)，上线保护要求见[部署运维](../deploy-prep.md)。本文不改变既有微博、白酒业务及部署规则。

## 1. 目标与状态约定

在当前项目的页面体系中提供个人投资记账功能，以「有知有行」的「有行」投资记账为产品参考，以已有半成品项目 `ChangZhang` 为需求和代码参考。保留资金进出记录与收益分析，通过持仓、现金及行情联动自动计算总资产，减少手工填写资产金额。

不是把半成品整套应用原样搬入，也不将消费记账作为当前目标。具体页面、路由、接口和首期范围尚未定稿。

| 状态 | 含义 |

| 已确认需求 | 用户明确表达或在澄清问题中选择的要求 |

| 设计约束 | 既有项目约束，或为避免错误核算必须满足的原则；具体操作方案仍可能待定 |

## 5. 收益指标与核验边界

### 5.1 官方公开口径

| 视角 | 区间指标 | 年化指标 | 依据 |
| --- | --- | --- | --- |
| 个人投资者 | Modified Dietz 资金加权收益率，考虑资金规模及投入时间 | XIRR | O2 |
| 基金经理 | TWR 时间加权收益率，按区间链乘，尽量排除外部资金进出影响 | TWR 复利年化 | O2 |

累计收益金额与收益率是不同指标。概念公式为：

```text
区间收益金额 = 期末资产 - 期初资产 - 区间净流入
Modified Dietz = 区间收益金额 / (期初资产 + 各笔现金流金额 × 时间权重之和)
TWR = 各子区间 (1 + 子区间收益率) 的乘积 - 1
```

T02/T04 已明确资金流后资产、期初期末、日数及舍入；T07 已按批准的日终资金边界链乘实现，前缀 Dietz 采用线性大数日矩累积，复合年化走精确路径或有界认证。具体边界、参考/不可用规则见 API 第 10 节，不要求另采历史事件日价格；实现与完整验收分别记录。

官方说明资金加权视角的年化采用 XIRR，不是把 Modified Dietz 机械复利年化。官方文档还说明超过半年才展示年化、资金加权曲线不展示最大回撤而 TWR 曲线保留；这些为参考规则，是否完整采用仍待确定。

### 5.3 计算设计约束

- 买卖股票与外部入金出金分开；在包含现金的同一账户内，普通买卖不构成外部现金流。
- 金额、股数、价格和汇率有不同精度需求，遵循既有架构的金额精度要求。
- 年度资金加权收益率不能通过两个累计收益率相减得到；汇总收益率不能简单平均成员账户收益率。
- XIRR 无解、多解或不收敛、零分母及估值不足必须显式处理，不能用零收益冒充有效结果。
- 比较指数时必须标识价格/全收益口径、币种、区间和日期对齐规则，不能只修改显示名称。

### 5.4 T04 实施口径（2026-09-07）

用户要求先解释设计再实施；本轮已经先说明下列方案，再实现累计收益、Modified Dietz 和独立 XIRR。既有已确认财务规则继续优先；以下边界及求解策略属于本轮明确说明的实施细化，不把参考产品的未决交互、半年门槛或全部算法当成用户逐项确认。

- 保留 T02 的外部正流入/负流出、同行资产 post-flow、稳定同日顺序、缺资产资金流仅沿用原额。内部买卖/留存分红不当投入，reported/holdings 不相加。
- 默认首个已知日终资产为基准，排除该日所有资金流；显式 from 使用此前最后资产，计算边界是 from 前一日日终，包含 from/to 的资金流。缺期初不反推，单点不伪造零收益。
- 终点使用实际最后资产/沿用记录，不延伸空白日期至今天。持仓观察后仍有流量却没有期末资产则不可用；不静默漏算已知流量。请求日期、计算边界和资产来源日期分开显示。
- 累计收益精确相减；Dietz 使用日终流量权重（期末日为零）、公历自然日和精确有理数，分母不大于零不可用。XIRR 使用投资者符号、同日精确净额、actual/365，不从 Dietz 年化。
- 沿用较早端点只标参考，原值不加资金流，因此入金未更新总资产时可能显示亏损。过期/未追踪端点阻止指标，非相关中间旧观察不自动阻止端点计算；追踪完整不代表行情是当日收盘。
- XIRR 使用有界二分和精度守卫；多次符号变化保守标记“可能多解、未证明唯一”，不凭简单扫描或任意 Newton 初值选根。无解、全零无信息、范围不足和未收敛分别说明。短于一年显示外推风险，不擅自采用“半年以前隐藏”的参考门槛。
- 图、卡片和计算现金流消费一个版本快照；只读计算，无新观察、缓存或历史覆盖。未实现收益曲线、TWR、基准及 T05 以后任务。具体字段/数值限制见 API 第 10 节；合成验证不能替代 G01 私有样本对账。

- E1 有账户元数据，以及「记总资产」「转入转出」两种记录。
- 记录包含记账日期、现金流金额、总资产、投资日志、创建时间和渠道明细；转出用负金额表示。
- 记账日期与创建时间可能相隔较久，存在补记；有同日多笔现金流和多次估值。
- 现金流记录可以附带总资产，也可能为空。空白不等于零，附带资产也不能一律当成独立的第二条估值。
- 初始资产可构成第一笔投入，导入时需要识别，不能重复入金。
- 渠道组织方式及是否包含现金的历史统计口径曾发生变化。
- 日志不是完整成交明细：可能合并多笔交易、只写手数、缺少证券代码，或明确说明遗漏、净额补记、分红再投和非现金股数变化。
- 最后资产记录日期早于导出日期；不能默认用导出日延长年化计算期限。
- 官方按真实日期计算、按周日绘图的说明与截图中的记录日/曲线末端日期差异相符；尚未逐点验证其打点算法。

### 6.2 当前导入与后续记录方案

直接导入历史总资产、转入和转出，保留原始记录，后续在本系统继续记总额与资金流。历史分红、送股和拆股不单独重建；从日志恢复成交、用历史行情回填资产均不在范围内。此前“先核对切换日持仓/现金再接分析”的建议已由 U25/U26 取代，不作为导入或历史收益的前置。

持仓自动计算只需要真实的当前持仓和现金来源，不要求补齐历史交易。reported/holdings 是能力字段，不是分析轨道；自动结果与导入和人工记录在同一物理表，不能生成假入金或以今日持仓改写导入金额。已有历史成交汇率功能不等于历史资产回填。

同日顺序、日期制式、幂等重试和逐条更正已实现；增量合并与整批撤销不再列为迁移缺口。汇总仍需要所选成员的账户数据，但不需要这些账户逐笔证券历史。

### 6.3 多账户对照发现

以下为 E1、E2 的结构核验，不包含真实数据值：

- 两账户记账起点不同，第二账户更早；两份导出的最后资产记录日相同，因而可以在共同终点对照资产合计，但早期历史覆盖并不相同。
- 两账户的中间估值日期并非一一对应。一个账户更新时，另一个可能只有较早和较晚的记录，不能直接按行号相加，也不能用未来记录冒充当日已知值。
- 第二账户有大量早期记录集中在后来的日期补录，进一步确认发生日期和创建时间必须分开。
- 存在同日相同资产金额但创建时间不同的记录；重复记录的判断与“重复上传同一个文件”的判断是两件事，不能只凭日期或金额删除原始记录。
- 第二账户有赎回资金拟用于另一账户投资的日志，另一账户有同日反向现金流，但金额并不相同。这只能构成待核对的转账候选，尚未由用户确认为同一笔实际调拨；日期接近、金额相近或日志用途相似都不是自动关联依据。
- 基金策略的“一份”“跟车”等文字不是结构化基金确认份额，不能直接用于基金净值自动估值。

### 6.4 已确认的汇总处理原则

#### 历史范围与成员关系

汇总是对所选底层账户的分析视图，创建时间不限制其历史覆盖。历史从最早成员的首次记录开始，其他成员从自己的首次记录起纳入；早期应标注实际覆盖的成员，不能用账户后来的资产倒填更早日期。

增减成员后，按新的成员范围重算历史资产、现金流分类、收益指标和曲线；不改写底层账户原始记录，也不因为创建汇总或加入成员生成一笔实际入金。

同一账户可以出现在多个汇总中。每个视图按底层账户身份去重；“全部资产”基于唯一底层账户计算，不能把彼此重叠的汇总卡片金额直接相加。

#### 自动与手工账户共存

自动账户用其有效持仓、现金和行情估值；手工账户继续接收总资产记录及资金进出。手工账户没有新的估值数据时，周六只提示待更新，不创建看似真实的新资产变化。

手工账户仍可参与 R14 的暂估汇总，但暂估属于派生结果，不写回并覆盖手工原始总额，也不等于完成一次真实资产更新。页面显示数据日期和状态，不建设提醒或推送通知渠道。

#### 账户间转账与汇总范围

已确认提供关联双方的转账记录，识别结果取决于查看范围：

| 查看范围 | 关联转账的性质 |
| --- | --- |
| 只看转出账户 | 对该账户为转出 |
| 只看转入账户 | 对该账户为转入 |
| 汇总同时包含双方 | 内部调拨，不增加汇总的外部投入或凭空产生收益 |
| 汇总只包含一方 | 相对于该汇总仍是外部流入或流出 |

当前转账功能按同一记账日完成设计，不引入在途状态或跨日到账管理。同日等额的正负现金流在数学上已能相消，显式关联还用于解释资金流向、避免虚增汇总投入/转出统计。

历史关联必须保留原始记录和日期。若发现跨日、非等额或不同币种记录，不得为了关联擅自改期、抹除差额或推定手续费；保留各自资金流及待核对说明，不扩展在途、复杂差额或跨币种转账流程。

#### 历史缺值暂估

对已经纳入某汇总的账户，在观察时点没有真实同日估值时，用户选择：

```text
暂估资产 = 截至观察时点最近一条有效资产记录
         + 该记录之后至观察时点的已知净转入
```

此式不假设缺失区间存在已知的市场涨跌，也不把推算金额当成新真实记录。同笔已填写总资产按 T02 为资金流后金额，不能重复加款；此处跨账户暂估与单账户缺值沿用原额的规则分开，不引入历史行情回填。

汇总应显示成员实际估值日期、暂估状态及覆盖范围。至少一个成员暂估时，不将汇总点标成全体真实同日估值；基于暂估值计算的收益指标也不能标为完全核实。首次记录之前的成员按 R15 标为尚未纳入历史范围，不以零资产伪装成已有真实估值。

手工记录之后发生的已记录划转应体现在相应账户暂估资产中，但汇总现金流分类仍按上面的内部/外部边界处理。同日完成的关联转账必须同时反映双方资产变化，不能漏掉一边而制造虚假盈亏；跨日在途管理不作为本次实现或验收前置要求。

### 6.5 汇总仍待确认的细节

- 全历史回溯、成员变化后重算、多汇总成员关系及底层去重已确认，不再作为未决项；账户归档或删除如何影响汇总仍需明确。
- 汇总显示币种及成员金额折算规则仍需明确，不能直接相加不同币种原额；这不等于跨币种转账，也不自动引入整段历史行情回填。转账只在现有同币种等额关联范围内处理。
- 暂估状态在收益卡、年度表、图表提示中的表现，以及历史补录后重算的范围；原应用在这些边界上的结果尚未核对。

## 7. 自动估值与交互建议

本节除 R03-R05、R07-R08、R11-R25 已明确部分外，为待讨论方案。必要的现金流分类与防止重复核算原则属于设计约束，不代表所有表单细节已经确认。

### 7.1 录入与估值分开

外部现金流、证券交易与资产估值需要独立表达。已确认转入时可同时记录买入股票和股数，不要求用户拆成多个页面；「使用现金买入」「卖出」「卖出并转出」的具体入口仍待设计。

参考 S10-S13 保留有/无资金进出的入口，但“没有资金进出”不等于“没有交易”：使用账户已有现金买入、卖出后将现金留在账户，都不构成外部资金流。内部交易需要可访问的录入入口，不能为了记股数强迫用户填一笔不存在的入金。

自动估值账户的资产区域展示持仓与现金计算结果及依据，手工估值账户仍填写资产金额。上次更新日期只用于提醒补记，不应成为禁止录入更早历史事件的限制。

#### 已确认的交易金额方式

用户输入证券、实际股数、实际成交价和可选费用，资金转入金额另记。同一结算币种下的概念关系为：

```text
买入扣款 = 股数 × 实际成交价 + 买入费用
卖出到账 = 股数 × 实际成交价 - 卖出费用
现金余额变化 = 外部净转入 - 买入扣款 + 卖出到账 + 其他已记录的现金变化
```

一次转入和买入可以组合提交，但买入支出不是第二笔投入，剩余资金保留在现金中。纯入金不强制关联股票；也不能因买入时现金不足而静默补造外部投入。费用未填写按零计算并标识未录入；费用币种及舍入细节由技术设计明确，不能称默认零为已核实实际无费用。

实际成交金额和费用用于更新现金；股数用于维护持仓；行情价格用于估值，三者不能混用。总资产的概念计算为：

```text
总资产（账户本位币）
= 各证券持仓数量 × 对应估值价格 × 对应汇率之和
+ 账户本位币现金余额
```

当前不引入转账在途状态或相应资产项。已有手工分红保留；历史总额已含的分红、送股和拆股不回溯。应收股息、融资及未来自动公司行动不列本轮排期，也不能当成新增投入。

### 7.2 总资产记录

- 每周六的职责是更新总资产，不再建设独立事件日前后采集或历史回填任务；保留现有手动刷新和写入后的刷新行为。
- 自动来源使用已明确的当前现金、持仓和可用报价，保存实际来源日期；具体时刻及休市取值在 T05 说明。手工来源无新值只显示未更新，不伪造新记录或推送提醒。
- 历史导入金额直接保留，后续新增总额延续分析；同一账户不同来源不得重复相加，也不能用今天行情解释过去。
- 行情缺失或部分更新失败不按零处理，不把不完整金额保存为成功记录。
- 同一周六计划任务重试需幂等，但不删除同日手工、导入或其他刷新记录；记录更正后的派生分析使用有效记录更新，不依赖已取消的 T06。

### 7.3 曲线与记录联动

- 已确认点选节点查看日期和收益，资金事件使用不同颜色；建议同时显示资产、基准、来源和相关日志。
- 建议红色标识投入、绿色标识转出，并配文字及正负号，不仅依赖颜色。
- 标记纵坐标对应该时点的收益率或累计收益，事件金额在提示明细中显示，不将金额画在百分比轴上。
- 建议同日多笔事件可以展开，支持从点位跳转当天记录及估值依据。
- 曲线记录日期、行情实际日期与按周聚合标签须能区分，不将估算或延用值包装为真实每日估值。

### 7.4 自动汇率折算

最新确认 U24/R28：腾讯替代此前 ECB 优先方案。当前总资产计算和今日操作使用最新报价，历史补记使用不晚于业务日期的最近日收盘；实际日期与请求日期分开展示，获取时间不是报价时间。编辑默认保留原快照，显式重新获取或改变币种/日期才重新选择。查询失败后允许明确手工填写，写入和幂等重试仍保留固定值。汇率查询、操作接入及股票当前总资产计算均已实现；保留这些能力，不因此建设已取消的历史资产回填。

已确认自动折算交易、持仓金额并保存所用汇率；用户进一步接受日度参考汇率，不要求盘中实时。账户仅维护本位币现金，不增加独立现金换汇操作。该方向是记账折算，不是连接券商执行真实换汇。

设计约束及仍待细化的边界：

- 原币金额、币种、折算金额及所用汇率应能区分；实时来源实际可能有延迟，需保存来源及时间，不能无条件宣称是可成交汇率。
- 已确认的历史交易折算值不能因之后汇率刷新而自行改变；新的资产估值可以使用该估值时点适用的汇率，历史更正需显式处理。
- 补记历史日期时，不用录入当天汇率冒充事件当日汇率；腾讯来源与失败后显式手工填写已确认并实现，不再作为未决项，不自动暂估或改写历史成交。
- 市场参考汇率可能不同于券商实际结算汇率。首批计算将可选费用记为成交原币；不同币种费用及实际扣款差异的更正方式仍需细化，自动折算不等于与券商账单精确一致。
- 不引入独立换汇流程，不等于可以把不同币种的原始金额直接相加；汇率不可用时的保存与提示策略需要明确。

### 7.5 手工分红与后续自动化

已确认首期手工录入分红。建议表单包含证券或分红来源、到账日期、币种、实际到账金额、备注；建议按实际到账税后金额增加相应现金，不先实现应收股息和分红税务计算。该字段集合和税后口径尚待用户确认。

在“持仓加现金”的账户边界下，核算必须区分：

| 操作 | 核算原则 |
| --- | --- |
| 现金分红留在账户 | 增加现金，是投资收益，不是外部入金 |
| 分红后取到账户外 | 先记录分红收入，再关联实际转出，不能重复增加收益 |
| 用分红现金继续买入 | 记录普通买入，不再生成一笔外部投入 |
| 手工总资产账户已将分红包含在本次总额内 | 不再向同一资产总额重复加一遍分红金额，独立分红明细的用途和交互需确定 |

用户此前提到腾讯自选股的自动分红，仅作为历史参考保留，未核实算法或来源。最新范围不回溯历史派息，导入总资产已包含的收益不再加一遍；未来自动分红和公司行动不在本轮排期。已有手工分红仅用于实际需要维护的持仓账户，不成为历史导入分析的必填步骤。

## 8. 架构与安全约束

- 沿用当前 Vue 页面与 Go 新业务模块方向；`ChangZhang` 的模型、公式和组件需逐项评估，不原样复制两套后端。
- 记账拥有独立业务数据边界，沿用架构中独立 SQLite 的方向，不写入微博库或白酒库；实际表结构和接口另行设计。
- 对证券、汇率和指数的需求不同于白酒采集，数据来源及历史深度需验证后再选型。
- 真实私有财务数据不能沿用公开行情的访问策略；承载这类数据前仍须有适当访问控制及 HTTPS 或受控 VPN，内部服务令牌和隐藏金额按钮不能代替保护。最新一期的空库/合成数据公网展示不以完整登录系统为开发前置，区别见下文。
- 日志、备份、导出、截图、异常报告和分享功能均按私有财务信息处理，真实附件不进入 Git 或镜像。
- 本文新增不表示认证、统一导航、数据迁移或自动记账已交付。

### 8.1 一期公网免登录目标

- 用户计划直接使用公网地址，不是仅在本机使用；一期不做登录、注册、角色或多用户授权，优先把已有后端能力接成可操作页面。
- 用户说明目前没有真实记账数据，允许别人查看。本期公网展示按空账本或明确标记的合成数据规划；不把此前提供的真实 Excel、截图或日志当成可公开样本，不因此删除或改造用户现有数据。
- 用户现已明确选择匿名共享全部读写，任何访客可以新增、更正、作废共享记录；不开发认证或用户访问控制，不以只读或隔离演示替换此决定。
- 匿名共享写入意味着任何访客均可改变账本，幂等键、版本号及 CSRF 不提供用户所有权隔离。事务校验、资源限制和防跨站保护仍保留；不由此公开已有私人附件、备份或日志。
- 当前后端仍为 `LEDGER_ENABLED=false` 默认关闭、启用后仅回环访问，Nginx 不代理记账。Vite 新增显式 `LEDGER_DEV_PROXY=true` 的本机代理，默认关闭且检查目标、实际 peer、Host 和跨源请求。公开入口及运行配置仍需专门适配和验证，本轮不执行提交、推送或部署。
- 在未来录入真实隐私数据之前重新确认访问范围；本期“无真实数据可以公开”的决定不是永久公开后续私人账本的授权。保留参数校验、事务、版本校验及合理资源限制，它们不是可因免登录而删除的登录功能。
